## c++三大特性

**封装**

最开始接触代码是C语言，那么开始写一些逻辑代码的时候会很麻烦，因为你要在函数中定义变量，然后按顺序写对应的逻辑，接着可以将逻辑封装成函数。当时会感觉很麻烦，因为很散装，知道后面学了struct结构体，把对应逻辑需要的数据可以放到一个结构体里面，这样就会比较好看。接着出现的问题就是数据封装到了一起，但是处理数据对应的逻辑即函数却还是在外面。因此就有了将数据和对应逻辑进行封装的类的出现。

封装就是将抽象得到的数据和行为相结合，形成一个有机的整体，也就是将数据与操作数据的源代码进行有机的结合，形成类，其中数据和函数都是类的成员，目的在于将对象的使用者和设计者分开，可以隐藏实现细节包括包含私有成员，使得代码模块增加安全指数，同时提高软件的可维护性和可修改性。

所以总结来说封装这个特性包含两三特点：

1. 结合性，即是将属性和方法结合 
2. 信息隐蔽性，利用接口机制隐蔽内部实现细节，只留下接口给外界调用   
3. 实现代码重用

**继承**

类的派生指的是从已有类产生新类的过程。原有的类成为基类或父类，产生的新类称为派生类或子类，子类继承基类后，可以创建子类对象来调用基类的函数，变量等。

一般来说有如下三种继承方式：

1. 单一继承：继承一个父类，这种继承称为单一继承，这也是我们用的做多的继承方式。
2. 多重继承：一个派生类继承多个基类，类与类之间要用逗号隔开，类名之前要有继承权限，假使两个或两个基类都有某变量或函数，在子类中调用时需要加**类名限定符**如obj.classA::i = 1；
3. 菱形继承：多重继承掺杂隔代继承1-n-1模式，此时需要用到虚继承，例如 B，C虚拟继承于A，D再多重继承B，C，否则会出错。后面有将具体虚继承怎么做。

**多态**

可以简单概括为“一个接口，多种方法”，即用的是同一个接口，但是效果各不相同，多态有两种形式的多态，一种是静态多态，一种是动态多态。

静态多态。静态多态的设计思想：对于相关的对象类型，直接实现它们各自的定义，不需要共有基类，甚至可以没有任何关系。只需要各个具体类的实现中要求相同的接口声明，静态多态本质上就是模板的具现化。

动态多态。对于相关的对象类型，确定它们之间的一个共同功能集，然后在基类中，把这些共同的功能声明为多个公共的虚函数接口。各个子类重写这些虚函数，以完成具体的功能。具体实现就是c++的虚函数。

多态是以封装和继承为基础实现的性质，一个形态的多种表现方式。硬要解释的话可以说是一个接口，多个功能，在用父类指针调用函数时，实际调用的是指针指向的实际类型（子类）的成员函数。

c++多态有以下几种：

1. 重载。函数重载和运算符重载，编译期。

2. 虚函数。子类的多态性，运行期。

   在继承关系中，对于父类的方法我们也同样使用。但是正常来说，我们希望方法的行为取决于调用方法的对象，而不是指针或引用指向的对象有关。

3. 模板，类模板，函数模板。编译期

> 比如你家有亲属结婚了，让你们家派个人来参加婚礼，邀请函写的是让你爸来，但是实际上你去了，或者你妹妹去了，这都是可以的，因为你们代表的是你爸，但是在你们去之前他们也不知道谁会去，只知道是你们家的人。可能是你爸爸，可能是你们家的其他人代表你爸参加。这就是多态。

### 协程解决什么问题

假设要实现网络请求：

```
Response request() {
    connect();
    send_request();
    Response response = receive_response();
    return response;
}
```

如果这些操作阻塞线程，那么等待网络期间，线程无法处理其他任务。

传统异步回调可能写成：

```
async_connect([&] {
    async_send([&] {
        async_receive([&](Response response) {
            process(response);
        });
    });
});
```

流程一多，就会出现：

- 回调嵌套；
- 状态需要手动保存；
- 错误传播复杂；
- 生命周期难管理；
- 业务逻辑被拆散。

使用协程后，可以把异步过程写成接近同步代码的形式：

```
Task<Response> request() {
    co_await async_connect();
    co_await async_send();

    Response response = co_await async_receive();

    co_return response;
}
```

线程遇到尚未完成的异步操作时，协程暂停，线程可以继续处理其他协程；异步操作完成后，再恢复原协程。

但要注意：

> `co_await` 本身不会把阻塞函数变成异步函数。

下面这种写法仍然会阻塞线程：

```
Task<void> foo() {
    ::sleep(10);   // 依然阻塞当前线程
    co_return;
}
```

必须有事件循环、线程池、IOCP、epoll 等组件配合，把“操作完成”转换成协程恢复。



## 先给一个最小实现

```
#include <coroutine>
#include <iostream>
#include <utility>

class Task {
public:
    // 编译器通过 promise_type 确定协程的行为
    struct promise_type {
        // 创建返回给调用者的 Task
        Task get_return_object() {
            return Task{
                std::coroutine_handle<promise_type>::from_promise(*this)
            };
        }

        // 协程创建后，先暂停，不立即执行函数体
        std::suspend_always initial_suspend() noexcept {
            return {};
        }

        // 协程执行结束后，保持暂停，等待 Task 析构时销毁
        std::suspend_always final_suspend() noexcept {
            return {};
        }

        // 协程没有返回值
        void return_void() noexcept {}

        // 协程内部出现未捕获异常
        void unhandled_exception() {
            std::terminate();
        }
    };

    using Handle = std::coroutine_handle<promise_type>;

    explicit Task(Handle handle) : handle_(handle) {}

    // 协程句柄不能被复制，否则会重复销毁
    Task(const Task&) = delete;
    Task& operator=(const Task&) = delete;

    // 允许移动所有权
    Task(Task&& other) noexcept
        : handle_(std::exchange(other.handle_, nullptr)) {}

    Task& operator=(Task&& other) noexcept {
        if (this != &other) {
            if (handle_) {
                handle_.destroy();
            }

            handle_ = std::exchange(other.handle_, nullptr);
        }

        return *this;
    }

    ~Task() {
        if (handle_) {
            handle_.destroy();
        }
    }

    // 继续执行协程
    bool resume() {
        if (!handle_ || handle_.done()) {
            return false;
        }

        handle_.resume();
        return !handle_.done();
    }

private:
    Handle handle_;
};
```

定义一个协程函数：

```
Task coroutine_test() {
    std::cout << "1. 协程开始\n";

    co_await std::suspend_always{};

    std::cout << "2. 协程恢复\n";
}
```

使用：

```
int main() {
    Task task = coroutine_test();

    std::cout << "main: 第一次恢复\n";
    task.resume();

    std::cout << "main: 第二次恢复\n";
    task.resume();

    std::cout << "main: 结束\n";
}
```

运行结果：

```
main: 第一次恢复
1. 协程开始
main: 第二次恢复
2. 协程恢复
main: 结束
```

### 通俗理解

对于一个协程任务，

```
分配协程帧
    ↓
保存函数参数
    ↓
构造 promise_type
    ↓
get_return_object()
    ↓
initial_suspend()
```

上面的这个过程就类似于ucontext的makecontext

#### `initial_suspend()` 和 `final_suspend()`

它们都是编译器自动插入的特殊 `co_await`。

协程函数逻辑上近似于：

```
Task coroutine_test() {
    // 编译器隐式执行
    co_await promise.initial_suspend();

    try {
        // 用户写的函数体
    } catch (...) {
        promise.unhandled_exception();
    }

    // 用户正常结束时
    promise.return_void();

    // 编译器隐式执行
    co_await promise.final_suspend();
}
```

co_await std::suspend_never{};

### co_return

在上面的例子里，

```
Task coroutine_test() {
    std::cout << "1. 协程开始\n";

    co_await std::suspend_always{};

    std::cout << "2. 协程恢复\n";

```

没写co_return，但是这里其实就相当于隐式在最后写了一个co_return;

它会调用：

```
promise.return_void();

promise.final_suspend();

要是写一个co_return a+b；这种呢，得到的结果用一个变量保存，然后这个变量是保存在协程帧里面，想拿到还得先拿到handle_.promise()，然后取里面的那个变量。



### co_yield

```
co_yield value;
```

大致会被编译器转换为：

```
co_await promise.yield_value(value);
```

所以要使用 `co_yield`，`promise_type` 必须提供：

```
yield_value()
```



所以在promise里面写一个

```
	// co_yield value 会调用这个函数
   std::suspend_always yield_value(int value) noexcept {
       current_value = value;
       return {};
   }
```

看到返回值是调用了一个std::suspend_always，

然后在promise里面写一个

```
 // 恢复协程，尝试产生下一个值
    bool next() {
        if (!handle_ || handle_.done()) {
            return false;
        }

        handle_.resume();

        return !handle_.done();
    }
```

就是恢复一下。



那么生成器函数：

```
Generator generate_numbers() {
    co_yield 10;
    co_yield 20;
    co_yield 30;
}
```

使用：

```
int main() {
    Generator generator = generate_numbers();

    while (generator.next()) {
        std::cout << generator.value() << '\n';
    }
}
```

输出：

```
10
20
30
```

其实就是程序运行了，协程方法执行，但是先std::suspend_always卡住了，next()里的resume方法先恢复协程，执行co_yield 10了，保存到变量里了，把函数挂起来。ok，next返回true了，打印一个值。



### 协程帧 `coroutine frame`

协程暂停之后，普通函数栈已经不能继续保存它的状态，因此编译器会创建一块协程状态空间，通常称为**协程帧**。

它大致保存：

```
协程当前执行到哪里
函数参数副本
需要跨越暂停点的局部变量
promise 对象
一些编译器内部状态
```

可以把一个协程想象成：

```
struct 编译器生成的协程帧 {
    int 当前状态;
    参数副本;
    局部变量;
    promise_type promise;
};
```



### `std::coroutine_handle`

`coroutine_handle` 可以理解为**协程帧的控制句柄**。

常见操作：

```
handle.resume();   // 恢复协程
handle.done();     // 是否已经到达最终暂停点
handle.destroy();  // 销毁协程帧
handle.promise();  // 访问 promise 对象
```

它内部通常可以理解为保存了一个指向协程帧的指针，但具体实现由编译器决定。标准提供了有类型和无类型两种句柄：

```
std::coroutine_handle<promise_type>
std::coroutine_handle<>
```

`resume()` 只能用于处于暂停状态的协程；`destroy()` 同样要求协程处于暂停状态，否则会产生未定义行为。



### Awaitable 和 Awaiter

`co_await expression` 最终需要得到一个 **Awaiter**。

Awaiter 一般提供三个函数：

```
struct Awaiter {
    bool await_ready();

    void await_suspend(std::coroutine_handle<> handle);

    Result await_resume();
};
```

三个函数分别控制：

```
await_ready   ：现在是否已经完成，可以不暂停？
await_suspend ：需要暂停时，把协程交给谁管理？
await_resume  ：恢复后，co_await 表达式得到什么结果？
```





## 全局变量需要注意什么，全局变量又有哪些优点

### 1. **全局变量需要注意的问题**

1. **作用域太大**
   - 在整个程序里都能访问，容易被任何地方改，导致 bug 难排查。
2. **生命周期太长**
   - 从程序开始到结束都存在，占用内存不释放，可能浪费资源。
3. **命名冲突**
   - 不同文件里如果有同名的全局变量，会引起链接错误或覆盖。
4. **多线程安全问题**
   - 多个线程同时读写全局变量时，可能产生竞争，需要加锁保护。
5. **可维护性差**
   - 程序大了之后，全局变量像“空气污染”，哪里都能用，代码逻辑会混乱。

------

### 2. **全局变量的优点**

1. **共享数据方便**
   - 各个函数、文件之间可以直接访问，不需要专门传参数。
2. **生命周期长**
   - 一直存在，可以保存全局状态，不会随着函数结束而销毁。
3. **实现简单**
   - 对小程序、测试代码，直接用全局变量能快速完成需求。



## 指针的大小

### 1. **指针的大小取决于 CPU 的位数**

- 在 **32位系统** 下，指针大小是 **4字节（32位）**，因为地址总线宽度是 32 位，能表示 2322^{32}232 个地址（约 4GB 内存空间）。
- 在 **64位系统** 下，指针大小是 **8字节（64位）**，因为地址总线宽度是 64 位，能表示更大的地址空间。

------

### 2. **例子**

```
#include <iostream>
using namespace std;

int main() {
    cout << sizeof(int*)    << endl;
    cout << sizeof(double*) << endl;
    cout << sizeof(char*)   << endl;
    return 0;
}
```

- 不管是什么类型的指针（`int*`、`double*`、`char*`），**大小都一样**，因为它们本质上都只是存放“地址”。
- 区别只是“解释地址时，取几个字节的数据”。

在 32 位机上输出都是 `4`，在 64 位机上输出都是 `8`。



## 循环引用是什么？

### 1. **定义**

**循环引用（Cyclic Reference / Circular Reference）**

- 是指两个或多个对象相互引用，形成一个环，使得引用计数机制无法正确释放内存。
- 结果：即使这些对象不再被程序其他部分使用，也不会被回收，造成 **内存泄漏**。

------

### 2. **示例（C++智能指针）**

```
#include <memory>
using namespace std;

struct B; // 前向声明

struct A {
    shared_ptr<B> b_ptr;  // A 持有 B
};

struct B {
    shared_ptr<A> a_ptr;  // B 持有 A
};

int main() {
    auto a = make_shared<A>();
    auto b = make_shared<B>();
    a->b_ptr = b;
    b->a_ptr = a;  // 循环引用
} // a 和 b 都不会被释放，造成内存泄漏
```

- **原因**：`shared_ptr` 使用引用计数，当计数不为 0 时不会释放对象。
- 这里 A 持有 B，B 又持有 A，计数永远不为 0 → 永远不释放。

------

### 3. **解决方法**

1. **弱引用 `weak_ptr`**
   - 用 `weak_ptr` 打破循环引用，弱引用不会增加计数：

```
struct B {
    weak_ptr<A> a_ptr; // 代替 shared_ptr
};
```

1. **手动管理**
   - 对象析构前手动断开引用，确保不会循环。





## 面向对象和面向过程语言的区别

首要要知道这两个都是一种编程思想

**面向过程**就是分析出解决问题所需要的步骤，然后用函数把这些步骤一步一步实现，使用的时候一个一个依次调用就可以了。

**面向对象**是把构成问题事务分解成各个对象，建立对象的目的不是为了完成一个步骤，而是为了描叙某个事物在整个解决问题的步骤中的行为。

**举一个例子：**

例如五子棋，面向过程的设计思路就是首先分析问题的步骤：1、开始游戏，2、黑子先走，3、绘制画面，4、判断输赢，5、轮到白子，6、绘制画面，7、判断输赢，8、返回步骤2，9、输出最后结果。把上面每个步骤用分别的函数来实现，问题就解决了。

而面向对象的设计则是从另外的思路来解决问题。整个五子棋可以分为 1、黑白双方，这两方的行为是一模一样的，2、棋盘系统，负责绘制画面，3、规则系统，负责判定诸如犯规、输赢等。第一类对象（玩家对象）负责接受用户输入，并告知第二类对象（棋盘对象）棋子布局的变化，棋盘对象接收到了棋子的i变化就要负责在屏幕上面显示出这种变化，同时利用第三类对象（规则系统）来对棋局进行判定。

可以明显地看出，面向对象是以功能来划分问题，而不是步骤。同样是绘制棋局，这样的行为在面向过程的设计中分散在了总多步骤中，很可能出现不同的绘制版本，因为通常设计人员会考虑到实际情况进行各种各样的简化。而面向对象的设计中，绘图只可能在棋盘对象中出现，从而保证了绘图的统一。功能上的统一保证了面向对象设计的可扩展性。

**面向过程**

优点：性能比面向对象高，因为类调用时需要实例化，开销比较大，比较消耗资源;比如单片机、嵌入式开发、 Linux/Unix等一般采用面向过程开发，性能是最重要的因素。

缺点：没有面向对象易维护、易复用、易扩展

**面向对象**

优点：易维护、易复用、易扩展，由于面向对象有封装、继承、多态性的特性，可以设计出低耦合的系统，使系统 更加灵活、更加易于维护

缺点：性能比面向过程低



## 结构体(struct)和联合体(union)的区别

结构体struct：把不同类型的数据组合成一个整体。struct里每个成员都有自己独立的地址。sizeof(struct)是内存对齐后所有成员长度的加和。（引申出[内存对齐](#说一说内存对齐)的问题）

共同体union：各成员共享一段内存空间, 一个union变量的长度等于各成员中最长的长度，以达到节省空间的目的。所谓的共享不是指把多个成员同时装入一个union变量内, 而是指该union变量可被赋予任一成员值,但每次只能赋一种值, 赋入新值则冲去旧值。 sizeof(union)是最长的数据成员的长度。

union里面同一时刻只保存一个变量，这个保存的变量可以叫做活动成员

```
union Data {
    int i;
    float f;
};

Data data;

data.i = 10;     // 此时有效成员是 i
data.f = 3.14f;  // 此时有效成员变成 f
```

使用就类似于结构体



2 什么时候用union？

比如电脑上来了一个事件，可能是鼠标事件，也可能是键盘事件，但是不可能两个都是，那么这时候就可以设置一个union，用到的时候专门设置，来达到节省内存的目的

3 更好的替代方案

std::variant

int main() {

}
```



## 结构体和类的区别

C++ 里结构体（`struct`）和类（`class`）本质上几乎是一样的，主要区别只有几个：

1. **默认访问权限不同**
   - `struct` 的成员默认是 **public**。
   - `class` 的成员默认是 **private**。
2. **默认继承方式不同**
   - `struct` 继承时默认是 **public 继承**。
   - `class` 继承时默认是 **private 继承**。
3. **语义习惯不同**（不是语法限制）
   - 一般用 `struct` 来表示数据的“集合”（像 C 语言里的结构体），更偏向“数据”。
   - 一般用 `class` 来表示带有行为和封装的对象，更偏向“面向对象”。

除此之外，两者支持的功能完全一样：可以有构造函数、析构函数、成员函数、静态成员、运算符重载、继承、多态等。







## struct的内存对齐规则

> ## 一、struct 内存对齐规则
>
> 在 C/C++ 中，struct 里每个成员变量都有自己的大小（比如 `int` 4 字节，`char` 1 字节），而内存对齐是为了让 CPU 访问更高效。规则大致如下：
>
> 1. **成员自身对齐**
>     每个成员在 struct 中的地址必须是它自身大小的倍数（或者特定平台要求的对齐数）。
>
>    - 例子：
>
>      ```
>      struct A {
>          char c;  // 1字节
>          int i;   // 4字节
>      };
>      ```
>
>      - `c` 在偏移 0 位置（ok）
>      - `i` 必须在 4 的倍数地址，所以前面会填充 3 个字节（padding）
>      - struct 总大小 = 8 字节（不是 5 字节，因为要考虑对齐和 padding）
>
> 2. **结构体整体对齐**
>     struct 的总大小必须是最大成员对齐数的整数倍。
>
>    - 上例中，最大成员是 `int`（4 字节对齐），所以 struct 大小要能被 4 整除 → 8 字节。
>
> 3. **填充（padding）**
>     为了满足以上规则，编译器会在成员之间或末尾自动加空白字节。
>
> ------
>
> ### 举例说明
>
> ```
> struct B {
>     char a;   // 1字节
>     short b;  // 2字节
>     int c;    // 4字节
> };
> ```
>
> - `a` 偏移 0 → ok
> - `b` 偏移 2 → 前面填充 1 字节
> - `c` 偏移 4 → ok
> - struct 总大小 = 8 字节（最大成员是 int，对齐 4 字节，8 可以被 4 整除）
>
> ------
>
> ## 二、为什么要对齐
>
> 1. **CPU 访问效率**
>    - CPU 访问内存通常按对齐地址读取（比如读取 4 字节 int 最好在能被 4 整除的地址）。
>    - 非对齐访问可能需要额外操作，慢很多，甚至某些架构会报错。
> 2. **硬件要求**
>    - 某些处理器（ARM、MIPS 等）不支持非对齐访问，必须按照对齐规则。
> 3. **保证结构体跨平台一致**
>    - 对齐让 struct 的内存布局可预测，方便直接读写内存或做序列化。



## arr和&arr[0]和&arr的不同

我们直接用一个例子讲清楚：

```
int arr[5]; // 假设起始地址是0x1000
```

------

### 1️⃣ `arr`

- **意思**：数组首元素的地址（自动退化为指针）
- **类型**：`int*`
- **值**：0x1000
- **运算**：`arr + 1` → 0x1004（跳到下一个 `int`）

------

### 2️⃣ `&arr[0]`

- **意思**：显式取首元素地址
- **类型**：`int*`
- **值**：0x1000
- **运算**：`&arr[0] + 1` → 0x1004（跳到下一个 `int`）

> ✅ `arr` 和 `&arr[0]` 在大多数表达式中完全一样

------

### 3️⃣ `&arr`

- **意思**：取整个数组的地址
- **类型**：`int (*)[5]`（指向 5 个 `int` 的数组）
- **值**：0x1000
- **运算**：`&arr + 1` → 0x1014（跳过整个数组 5 × 4 字节 = 20 字节）

------

### 🔹 内存布局对比

```
arr / &arr[0]      : 0x1000  -> 第0个元素
arr + 1 / &arr[0]+1: 0x1004  -> 第1个元素
&arr               : 0x1000  -> 整个数组
&arr + 1           : 0x1014  -> 整个数组后的地址
```

------

**总结**：

- `arr` 和 `&arr[0]` → 指向第一个元素，类型 `int*`
- `&arr` → 指向整个数组，类型 `int (*)[5]`，算地址时跳整个数组



## char a,char a[],char *a,char *[],char * *a 之间的区别

1. ------

   ## 1️⃣ `char a`

   - **类型**：单个字符 `char`
   - **含义**：一个 1 字节的变量
   - **例子**：

   ```
   char a = 'x';
   ```

   - **用途**：存储单个字符

   ------

   ## 2️⃣ `char a[]`

   - **类型**：字符数组
   - **含义**：连续存放多个字符，大小在定义时确定或在初始化时由内容推导
   - **例子**：

   ```
   char a[] = "hello"; // 实际大小 6，包括 '\0'
   ```

   - **注意**：`a` 在大多数表达式中会 **退化为 `char\*`**，指向第一个元素

   ------

   ## 3️⃣ `char *a`

   - **类型**：字符指针
   - **含义**：指向某个字符（通常是字符串首字符）的地址
   - **例子**：

   ```
   char *a = "hello"; // 指向字符串常量的首地址
   ```

   - **区别**：`char a[]` 是数组空间存储字符，`char *a` 只是指针指向字符
   - **用途**：可以指向不同字符串，灵活，但要注意不要修改常量字符串

   ------

   ## 4️⃣ `char *[]`

   - **类型**：字符指针数组
   - **含义**：数组中每个元素都是 `char*`（指向字符串）
   - **例子**：

   ```
   char *arr[] = {"one", "two", "three"};
   ```

   - **用途**：存放多个字符串的地址
   - **注意**：数组名 `arr` 退化成 `char**`（指向指针数组的首地址）

   ------

   ## 5️⃣ `char **a`

   - **类型**：指向指针的指针
   - **含义**：指向一个 `char*` 的地址
   - **例子**：

   ```
   char *arr[] = {"one", "two"};
   char **a = arr; // 指向指针数组的首元素
   ```

   - **用途**：访问多个字符串（如 `argv` 就是 `char** argv`）

   ------

   ## 🔹 总结对比表

   

   | 写法       | 类型       | 指向/存储 | 用途                         |
   | ---------- | ---------- | --------- | ---------------------------- |
   | `char a`   | `char`     | 单个字符  | 存一个字符                   |
   | `char a[]` | `char[]`   | 多个字符  | 字符数组（可存字符串）       |
   | `char *a`  | `char*`    | 指向字符  | 指向字符串或字符             |
   | `char *[]` | `char* []` | 指针数组  | 存多个字符串的地址           |
   | `char **a` | `char**`   | 指向指针  | 访问指针数组（多字符串操作） |





## 一维数组名和二维数组名的区别

好的，我们直接讲 **一维数组名和二维数组名的区别**，重点在于类型和指针运算。

------

假设有：

```
int arr1[5];      // 一维数组
int arr2[3][5];   // 二维数组
```

------

### 1️⃣ 一维数组名 `arr1`

- **类型**：`int[5]`
- **在大多数表达式中退化为**：`int*`（指向首元素）
- **值**：首元素地址 `&arr1[0]`
- **运算**：`arr1 + 1` → 地址增加 `sizeof(int)`（下一个元素）

------

### 2️⃣ 二维数组名 `arr2`

- **类型**：`int[3][5]`
- **在大多数表达式中退化为**：`int (*)[5]`（指向长度为 5 的一维数组的指针）
- **值**：首行地址 `&arr2[0]`
- **运算**：`arr2 + 1` → 地址增加 `5 * sizeof(int)`（跳到下一行）

------

### 🔹 内存示意

假设每个 `int` 4 字节：

```
arr1: [0] [1] [2] [3] [4]
      ↑ arr1 / &arr1[0]
arr1 + 1 → 下一个 int (4字节后)

arr2:
行0: [0][1][2][3][4]
行1: [5][6][7][8][9]
行2: [10][11][12][13][14]
↑ arr2 / &arr2[0]
arr2 + 1 → 跳过整行（5*4=20字节）
```

------

### 🔹 总结

| 数组        | 类型退化     | `+1` 增加                 |
| ----------- | ------------ | ------------------------- |
| 一维 `arr1` | `int*`       | 下一个元素（4字节）       |
| 二维 `arr2` | `int (*)[5]` | 下一个一维数组（5*4字节） |

> 核心区别：**一维数组名退化成指向元素的指针，二维数组名退化成指向子数组的指针**。

其实就是数组的指针和指针的数组

数组的指针：指向一个数组的指针就是数组指针

## C++ 程序的内存分段

一个 C++ 程序在运行时，内存大致分为以下几段：

```
|--------------------------|
|      栈（Stack）         |
|--------------------------|
|      堆（Heap）          |
|--------------------------|
|   BSS（未初始化全局区）   |
|--------------------------|
|   数据段（已初始化全局区）|
|--------------------------|
|       代码段（Text）      |
|--------------------------|
```

### 1️⃣ 代码段（Text Segment）

- **内容**：程序的机器指令（函数代码）
- **特点**：只读、共享，多进程可共享同一份
- **示例**：`main() { ... }` 函数的指令存这里

------

### 2️⃣ 数据段（Data Segment）

- **内容**：已初始化的全局变量、静态变量
- **特点**：程序加载时就分配好空间
- **示例**：

```
int g_val = 10;     // 存在数据段
static int s_val=5; // 静态变量也在这里
```

------

### 3️⃣ BSS 段（Block Started by Symbol）

- **内容**：BSS 通常存放未显式初始化或零初始化的全局变量和静态变量。
- **特点**：程序加载时自动初始化为 0
- **示例**：

```
int g_uninit;       // BSS 段
static int s_uninit; // BSS 段
```

------

### 4️⃣ 堆（Heap）

- **内容**：动态分配的内存，用 `new` / `malloc` 分配
- **特点**：程序员控制生命周期，手动释放
- **示例**：

```
int* p = new int[10]; // 堆上分配 10 个 int
```

------

### 5️⃣ 栈（Stack）

- **内容**：函数局部变量、函数调用信息（返回地址、参数）
- **特点**：先进后出（LIFO），自动分配和释放
- **示例**：

```
void func() {
    int a = 5; // 栈上分配
}
```

## **static 和const分别怎么用，类里面static和const可以同时修饰成员函数吗**

- ## 1️⃣ `static` 用法

  ### （1）全局/函数外变量

  ```
  static int g_val = 10;
  ```

  - **作用**：限制变量作用域在本文件，文件外不可见
  - **生命周期**：整个程序运行期间一直存在

  ### （2）函数内局部变量

  ```
  void func() {
      static int cnt = 0;
      cnt++;
      std::cout << cnt << std::endl;
  }
  ```

  - **特点**：只初始化一次，函数调用结束不会销毁，下次调用保留上次值

  ### （3）类成员

  ```
  class A {
  public:
      static int s_val; // 所有对象共享
  };
  int A::s_val = 0; // 类外初始化
  ```

  - **特点**：属于类，不属于对象
  - **访问**：`A::s_val` 或 `对象名.s_val`

  ------

  ## 2️⃣ `const` 用法

  ### （1）常量

  ```
  const int a = 10;
  ```

  - **特点**：不可修改

  ### （2）指针/引用修饰

  ```
  const int *p;  // 不能通过 p 修改这个地址的值，常量指针，const修饰的*p（*p算是取地址了，就是地址里面的不能动）
  int *const p;  // p这个指针不能指向其他地址，指针常量，const修饰的p这个指针
  ```

  ### （3）类成员函数

  ```
  class A {
      int x;
  public:
      int getX() const { return x; } // 不修改对象成员
  };
  ```

  - **特点**：保证函数不会修改对象成员变量
  - **可以调用对象的 const 方法**

  ------

  ## 3️⃣ 类里面 `static` 和 `const` 是否可以同时修饰成员函数

  ✅ 可以，但需要理解区别：

  ```
  class A {
  public:
      static int getValue() { return 10; }      // static 成员函数
      int getX() const { return x; }            // const 成员函数
  };
  ```

  - **`static` 成员函数**
    - 不依赖对象，不能访问非静态成员
    - 调用方式：`A::getValue()`
  - **`const` 成员函数**
    - 依赖对象，但保证不修改对象成员
    - 调用方式：对象调用 `obj.getX()`

  ❌ **需要注意，不能同时使用 `static` 和 `const` 修饰同一个成员函数**

  - 原因：`static` 不属于对象，没有 `this` 指针
  - `const` 修饰函数本质是限定 `this` 指针不能修改对象
  - 所以两者冲突

  ------

  ### 🔹 总结口诀

  - `static` → 静态的，共享的，不依赖对象
  - `const` → 不可修改，保证安全
  - 类成员函数：
    - `static` + `const` ❌
    - 非静态函数可以 `const`





## static初始化时机和线程安全问题

### 1️⃣ static 变量初始化时机

#### （1）全局/文件级别的 static

```
static int g_val = 10;
```

- **初始化时机**：程序加载阶段（**main() 之前**）
- **特点**：
  - 在程序开始运行前就已经分配内存并初始化
  - 生命周期贯穿整个程序

------

#### （2）函数内局部 static

```
void func() {
    static int cnt = 0; // 局部 static
    cnt++;
}
```

- **初始化时机**：第一次执行到该语句时（**惰性初始化**）
- **特点**：
  - 只初始化一次
  - 后续函数调用不会再初始化
  - 生命周期贯穿整个程序

> ⚠️ 注意：如果初始化依赖其他全局变量，要注意顺序问题

------

### 2️⃣ 线程安全问题

### （1）C++11 之前

- 局部 static 变量 **初始化不是线程安全的**
- 多线程同时第一次访问可能导致初始化被执行多次或竞态条件

```
void func() {
    static int cnt = expensiveInit(); // 线程不安全
}
```

- **解决方法**：
  - 使用互斥锁（mutex）保护初始化
  - 或者在 main() 之前初始化（全局变量）

------

### （2）C++11 之后

- **保证线程安全**（magic statics）
- 局部 static 的初始化在第一次被调用时，编译器会保证：
  - 只有一个线程进行初始化
  - 其他线程会等待初始化完成

```
void func() {
    static int cnt = expensiveInit(); // C++11 后线程安全
}
```

- ⚠️ 只保证初始化本身线程安全，不保证之后对该变量的操作线程安全

------

### 🔹 总结

| static 类型     | 初始化时机             | 线程安全                     |
| --------------- | ---------------------- | ---------------------------- |
| 全局/文件级别   | 程序加载阶段（main前） | 初始化线程安全（单线程）     |
| 函数局部 static | 第一次执行到该语句     | C++11 前不安全，C++11 后安全 |

## C++中局部静态变量的问题

### **首先说一下局部静态变量的理解**

位于 **静态存储区**（静态区/全局区），生命周期贯穿整个程序运行。

**初始化**：未显式初始化时，会自动初始化为 0。

**作用域**：仍然是局部的，只能在定义它的函数或代码块内访问。

**特点**：函数或代码块结束时，作用域结束，但变量的值不会被销毁，仍保留在内存中，直到程序结束。

**访问限制**：作用域外无法访问该驻留的值。

### **局部静态变量的构造和析构**

- **全局静态变量**：程序启动时构造，程序结束时析构。
- **局部静态变量**：第一次执行到定义处时构造，其析构在程序结束时进行。
- **顺序特点**：
  1. 构造顺序：取决于程序实际执行路径（不同函数调用、消息驱动或多线程程序可能不同）。
  2. 析构顺序：与构造顺序相反。
- **问题**：
  - 执行路径多变，构造顺序不可预知。
  - 局部静态变量分布在程序各处，彼此关联不明显，容易被忽略，可能导致意外。
- **建议**：尽量少使用局部静态变量，避免复杂依赖。

------

### **函数局部静态变量的返回**

```
int tmp() {
    static int b = 5; // 局部静态变量
    return b;
}

int main() {
    static int a = 0; // main 中的局部静态变量
    int c = tmp();     // 调用 tmp()
    std::cout << "a:" << a << std::endl;
    std::cout << "c:" << c << std::endl;
}
```

- 局部静态变量在函数外不可访问，但可以通过返回值使用其值。
- **编译器行为**（如 g++）：函数可以返回局部静态变量的值，因为它仍在静态存储区中，生命周期贯穿整个程序。



## **Const与指针**

### 1. 指针常量（p不能动）

👉 **指针指向的位置本身不能改，但它指向的内容可以改。**

写法：

```
int a = 10;
int b = 20;
int* const p = &a; // 指针常量
```

- `p` 一旦初始化指向 `a`，就不能再改指向别的地方
- 但是 `*p` 的值可以改

例子：

```
*p = 100;   // ✅ 可以改 a 的值
p = &b;     // ❌ 错，p 不能指向别的变量
```

口诀：**指针自己不能动，指向内容能动。**

------

### 2. 常量指针（*p不能动）

👉 **指针可以改，但它指向的内容不能通过这个指针改。**

写法：

```
int a = 10;
const int* p = &a; // 常量指针
```

- `p` 可以指向别的变量
- 但是 `*p` 的值不能通过 `p` 改

例子：

```
*p = 100;   // ❌ 错，不能改 a 的值
p = &b;     // ✅ 可以让 p 指向 b
```

口诀：**指针自己能动，指向内容不能动。**

------

### 3. 二合一（最严格）

既不能改指向，也不能改内容：

```
const int* const p = &a;
```

口诀：**都不能动。**

### 1️⃣ `#define` 宏常量

  - **预处理器处理**，在编译前直接替换文本

  - 不占内存（只是文本替换）

  - 类型检查，减少错误

  - 支持类成员常量，安全性更高

| 特性         | `#define` | `const`            |

✅ **结论**：

- **现代 C++ 中优先用 `const` 定义常量**

## typedef与#define的区别

**typedef**

typedef故名思意就是类型定义的意思，但是它**并不是定义一个新的类型而是给已有的类型起一个别名**。主要有两个作用，第一个是给一些复杂的变量类型起别名，起到简化的作用。第二个是定义与平台无关的类型，屏蔽不同平台之间的差异。在跨平台或操作系统的时候，只需要改typedef本身就可以

**#define**

#define为一宏定义语句，本质就是文本替换

**区别**

1. 关键字typedef在编译阶段有效，由于是在编译阶段，因此typedef有类型检查的功能。\#define则是宏定义，发生在预处理阶段，也就是编译之前，它只进行简单而机械的字符串替换，而不进行任何检查。

2. #define没有作用域的限制，只要是之前预定义过的宏，在以后的程序中都可以使用。而typedef有自己的作用域。

3. 对指针操作不同。见下面代码

```c++
typedef int * pint;

const PINT p2 = &i2;	//p可以更改，p指向的内容不能更改，相当于 const int *p；或 int const *p；
```

**定义类型别名用 `typedef`**（C++11 可以用 `using` 更现代）

**`#define` 更适合定义宏或常量**

## 左值引用和右值引用

### **左值引用**

左值引用分为：左值引用和常量左值引用(不希望被修改)

观察下列代码：

```c++
//左值引用
int a = 10;
int &b = a;  // 定义一个左值引用变量
b = 20;      // 通过左值引用修改引用内存的值

//常量左值引用
const int temp = 10; 
const int &var = temp;
```

### **右值引用**

#### 1️⃣ 左值引用（lvalue reference）

```
int a = 10;
int &lref = a;  // 左值引用
lref = 20;      // 可以修改 a
```

- **语法**：`T &ref = x;`
- **特点**：
  1. 必须绑定到 **左值**（有名字、可取地址的对象）
  2. 可以通过引用修改原对象
- **用途**：
  - 函数参数传引用，避免拷贝
  - 修改函数外部变量

------

#### 2️⃣ 右值引用（rvalue reference）

```
int &&rref = 10; // 右值引用，绑定到右值
```

- **语法**：`T &&ref = expr;`
- **特点**：
  1. 必须绑定到 **右值**（临时对象或字面量）
  2. 允许移动语义，减少拷贝开销
- **用途**：
  - 移动构造函数 / 移动赋值
  - 延长临时对象生命周期

------

#### 3️⃣ 对比总结

| 特性             | 左值引用 (`&`)   | 右值引用 (`&&`)        |
| ---------------- | ---------------- | ---------------------- |
| 可绑定对象类型   | 左值             | 右值                   |
| 是否可以修改对象 | ✅                | ✅                      |
| 主要用途         | 传引用、修改变量 | 移动语义、延长临时对象 |
| 语法示例         | `int &ref = a;`  | `int &&ref = 10;`      |

------

#### 4️⃣ 使用示例：移动语义

```
class String {
    char* data;
public:
    String(const char* s);               // 构造函数
    String(String&& other) {             // 移动构造
        data = other.data;
        other.data = nullptr;
    }
};
```

- `String&& other` 是右值引用
- 可以“抢走”临时对象的数据，避免拷贝

------

✅ **口语理解**：

- **左值引用** = “指向有名字的东西的引用”
- **右值引用** = “指向临时值的引用，可以移动资源”



## 深拷贝和浅拷贝

**浅拷贝**：只复制成员变量的值。成员里有指针时，复制的是**地址**。

**深拷贝**：另外申请一块内存，再把指针指向的**内容**复制过去。

关键问题只有一个：

> 复制完成后，两个对象内部的指针，是不是指向同一块内存？



在未定义显示拷贝构造函数的情况下，系统会调用默认的拷贝函数——即浅拷贝，它能够完成成员的一一复制。

当数据成员中没有指针时，浅拷贝是可行的；

**但当数据成员中有指针时，会出问题。如果没有自定义拷贝构造函数，会调用默认拷贝构造函数，这样就会调用两次析构函数。**第一次析构函数delete了内存，第二次的就指针悬挂了。所以，此时，必须采用深拷贝。

深拷贝与浅拷贝的区别就在于深拷贝会在堆内存中另外申请空间来储存数据，从而也就解决了指针悬挂的问题。简而言之，当数据成员中有指针时，必须要用深拷贝。

## c++中四种变量存储类型总结

在C++语言中，变量的存储类共有如下四种： 

（1）auto存储类（自动存储类）

（2）static存储类 （静态存储类）

（3）extern存储类  (外部存储类)

（4）register存储类（寄存器存储类）

- **自动存储类**

  auto存储类，即自动存储类。在函数内部定义的变量，如果不指定其存储类，那么它就是auto类变量。这个是最常见的，所以我们不加关键字auto

  这是我们经常见到的一种变量存储类型。见如下代码：

  ```c++
  void func( ) { int a; auto int b; … }
  //a和b都是auto存储类变量
  ```

  > 自动存储类在在进入代码块（函数）之前生成，在函数体内部存活，出了函数体（函数返回）后就消失。
  >
  > 自动变量默认初始值是不确定的、
  >
  > 自动存储类每调用一次函数时都要赋一次初始值

- **静态存储类**

  static关键字在c和c++中是不同的，这个在上面说过了，具体的话可以去看上面。

- **extern存储类**

  如果在一个文件中要引用另一个文件中定义的外部变量，则在此文件中应用extern关键字把此变量说明为外部的。例如：

  ```c++
  extern int a; //a为别的文件中定义的外部变量
  int mydata; //外部变量的定义 
  extern int mydata;  //外部变量的说明 
  ```
  
  > 大型程序为了易于维护和理解，通常需要把程序划分为多个文件来保存，每个文件都可以单独编译，最后再把多个文件的编译结果（即目标文件）连接到一起来生成一个可执行程序。这种情况下，如果在一个文件中需要引用另一个文件中的外部变量，就需要利用extern说明。
  
- **register存储类**

  ## 1️⃣ 定义
  
  ```
  register int a = 10;
  ```
  
  - **用途**：告诉编译器把该变量尽量存放在 **CPU 寄存器** 中，而不是栈上
  - **作用**：加快访问速度，适合频繁使用的局部变量



## C++中this指针相关问题

### This指针的来源

通过转化成c语言好理解一点。早期还没有针对特定c++的编译器，因此编译c++的时候都先翻译成c语言，再进行编译。

对于class结构来说，c语言中与之对应的就是结构体。

类中的成员变量可以翻译成结构体域中的变量，但是结构体中没有成员函数这个概念，因此成员函数就翻译成为全局函数。

那么如果函数内部想使用成员数据，可以使用该对象指针的方式，指向成员变量。

**其作用就是指向非静态成员函数所作用的对象。**

1. `this` 指针是一个隐含于每一个非静态成员函数中的特殊指针。它指向**调用该非静态成员函数的那个对象。**
2. 当对一个对象调用成员函数时，编译程序先将对象的地址赋给 `this` 指针，然后调用成员函数，每次成员函数存取数据成员时，都隐式使用 `this` 指针。
3. `this` 并不是一个常规变量，而是个右值，所以不能取得 `this` 的地址（不能 `&this`）。



### this` 是指针，`*this 是当前对象

### this指针是什么时候创建的？

生命周期 = 成员函数调用期间

### this指针存放在何处？堆、栈、全局变量，还是其他？

`this` 指针的存放位置依赖编译器实现：

- 可能存 **栈**
- 可能存 **寄存器**
- 不会作为全局变量存在

在汇编层面，它只是一个值（立即数、寄存器值或内存地址），与高级语言变量对应不完全一致

### 如果我们知道一个对象this指针的位置，可以直接使用吗？

**成员函数外无法使用**：对象本身无法访问 `this` 指针

**成员函数内可使用**：可以通过 `this` 或 `&this`（取指针本身的地址）访问

### 在成员函数中调用delete this会出现什么问题？

成员函数中调用 `delete this` 会释放对象内存：

- 在 `delete this` 之后，如果再访问对象成员或虚函数，会导致未定义行为

### 如果在类的析构函数中调用delete this，会发生什么？

会导致无限递归调用析构函数 → 堆栈溢出 → 系统崩溃



##  inline 内联函数与宏定义

### 1️⃣ 宏定义

```
#define SQUARE(x) ((x)*(x))
```

- **本质**：预处理器指令，编译前直接文本替换
- **优点**：
  - 不占函数调用开销
  - 简单快捷
- **缺点**：
  - **不做类型检查** → 容易出错
  - 调试困难（宏展开后看不到函数名）
  - 表达式容易出错（优先级问题）

```
int a = 3;
int b = SQUARE(a+1); // 展开为 ((a+1)*(a+1))，正确
int c = SQUARE(++a); // 展开为 ((++a)*(++a))，产生副作用
```

------

### 2️⃣ 内联函数 (`inline`)

```
inline int square(int x) { return x*x; }
```

- **本质**：函数调用在编译时尽量被展开，避免调用开销
- **优点**：
  - **有类型检查**，更安全
  - 调试友好，可用断点
  - 支持复杂表达式，不易出错
- **缺点**：
  - 过大函数不适合内联 → 会增大可执行文件
  - 编译器只是“建议”内联，不保证一定展开

✅ **口语总结**：

- **宏定义** = “纯文本替换，方便但危险”
- **内联函数** = “小函数、自动展开，安全又高效”
- **现代 C++ 优先使用 `inline` 函数代替宏**



### inline的重要性

`inline` 现在最重要的作用，**不是让函数“直接展开”提高速度**，而是：

> 允许同一个函数的完整定义出现在多个 `.cpp` 文件中，而不会造成重复定义错误。

`inline` 告诉编译器和链接器：

> 这个函数可能在多个编译单元中出现相同的定义，请把它们看作同一个函数。

因此，小函数可以直接把定义放在头文件里。



##  struct 和 typedef struct

###  1️⃣ C 语言里的写法

```
// 定义结构体
struct Person {
    char name[20];
    int age;

// 使用时必须加 struct 关键字
struct Person p1;
```

- **特点**：
  - 在 C 语言里，结构体类型名 **前面必须加 `struct`**
  - 不加 `struct` 会报错

------

### 2️⃣ typedef 简化写法

```
typedef struct Person {
    char name[20];
    int age;
} Person;  // 给类型取别名

// 使用时可以直接写类型名
Person p2;
```

- **作用**：
  - `typedef` 给结构体类型起一个别名
  - 使用时就不用写 `struct` 了，更简洁

------

### 3️⃣ C++ 中的情况

- **C++ 不需要 `typedef`**，因为结构体类型默认可以直接用名字：

```
struct Person {
    char name[20];
    int age;
};

Person p3; // 直接用类型名，不用 typedef
```

- 所以在 C++ 中，`typedef struct` 更多是为了兼容 C 语言或者习惯写法



## explicit 关键字

### 1️⃣ 定义

- **`explicit`** 用于 **构造函数或转换函数**
- 作用：**禁止构造函数被隐式调用**，避免类型自动转换

```
class A {
public:
    explicit A(int x) { }
};

A a1 = 10;   // ❌ 错误，不能隐式转换
A a2(10);    // ✅ 正确，显式调用
```

------

### 2️⃣ 为什么需要 explicit

- 如果没有 `explicit`，单参数构造函数可以被 **隐式转换**：

```
class B {
public:
    B(int x) { }
};

void func(B b) { }

func(10);    // ✅ 自动将 10 转换成 B 对象
```

- **风险**：
  - 可能出现意外类型转换
  - 导致代码难以阅读或潜在错误

## friend友元类和友元函数

`friend` 用来 **打破类的访问权限限制**，让指定函数或类可以访问私有成员（`private` 和 `protected`）。

------

### 1️⃣ 友元函数（Friend Function）

- **定义**：在类内声明某个函数是友元，允许该函数访问类的私有成员
- **语法**：

```
class A {
private:
    int x;
public:
    A(int val) : x(val) { }
    friend void printX(const A& a); // 声明友元函数
};

void printX(const A& a) {
    std::cout << a.x << std::endl; // 可以访问 private 成员
}
```

- **特点**：
  1. 不是类成员函数
  2. 可以访问类的私有和保护成员
  3. 需要在类内声明 `friend`

------

### 2️⃣ 友元类（Friend Class）

- **定义**：将一个类声明为友元类，友元类的所有成员函数都可以访问另一个类的私有成员
- **语法**：

```
class B; // 前向声明

class A {
private:
    int x;
public:
    A(int val) : x(val) { }
    friend class B; // B 是友元类
};

class B {
public:
    void showX(const A& a) {
        std::cout << a.x << std::endl; // 可以访问 A 的 private
    }
};
```

- **特点**：
  1. B 类的所有成员函数都可以访问 A 的私有成员
  2. 友元关系是单向的（B 可以访问 A，A 不可以访问 B）



## c++虚函数

虚函数：就是通过基类指针或基类引用（Animal* p = &dog;）去调用虚函数的时候，程序会根据实际类型去选择具体调用父类还是子类的哪个函数



### 虚函数的一些问题

- **构造函数可以设置为虚的吗？**

  答：不能。因为调用构造函数本来就是一个已知的类型，虚函数依赖于已经存在的对象，构造函数都还没有创建出这个对象，根本没办法用，所以构造函数是不能是虚函数的，先有鸡还是先有蛋的问题这属于。

  子类的默认构造函数总要执行的操作：执行基类的代码后调用父类的构造函数。


- **c++虚析构函数**

  如果要被析构的类的类型是父类，如下

  ```cpp
  Base* p = new Derived; 
  
  delete p;
  ```

  则基类析构函数必须是虚函数

  ```cpp
  class Base { public: virtual ~Base() = default; };
  ```

  声明一个虚析构函数，是为了确保释放派生对象时，按照正确的顺序调用析构函数。

  如果析构函数不是虚的，那么编译器只会调用对应指针类型的虚构函数。而其他类的析构函数就不会被调用。例如如下代码：	

  ```c++
  Employee* pe = new Singer;
  delete pe;
  ```

  只会调用Employee的析构函数而不会调用Singer类的析构函数。

  本来就是想当成Singer用的，结果只当成Employee给释放了，所以就可能出问题。




- **哪些函数不能是虚函数？**

  1. 构造函数
  2. 静态成员函数，不属于某个具体对象，没有 `this` 指针，因此不能参与基于对象动态类型的虚函数调用。
  3. 非成员函数。只有在一个类里的才能用virtual，类外的全局方法，不行。
  4. 友元函数。因为友元函数不算一个类的成员函数。
  5. 模板函数。因为虚函数表的关系，虚函数表需要为每个函数指定一个具体的位置，但是模板，可能根据模板实例化出任何函数出来，没有固定的虚函数表入口。

  ### 虚函数表和虚函数指针

  常见实现方式

  C++ 标准没有强制规定必须使用虚函数表，但主流编译器一般使用：

  - 虚函数表：`vtable`
  - 虚函数表指针：`vptr`

  可以把它简化理解为：

  ```
  对象中的 vptr（指向那个虚函数表）
         │
         ▼
  虚函数表 vtable
         │
         ├── Base::func1 地址
         ├── Base::func2 地址
         └── Base::~Base 地址
  ```

  当程序通过基类指针调用虚函数时，编译器生成的代码会通过 `vptr` 找到虚函数表，再找到对应的函数入口。

  

- **虚函数表是共享还是独有的？**

  同一个类的对象共享相应的虚函数表

  每个多态对象内部保存自己的虚表指针 `vptr`

  派生类通常有自己的虚函数表：

  ```
  Base 对象    → Base 虚函数表
  
  Derived 对象 → Derived 虚函数表
  ```

  

- **虚函数表和虚函数指针的位置？**

  虚函数表通常由编译器生成，并存放在程序的只读数据区域或其他静态存储区域。

  而对象的 `vptr` 通常作为隐藏数据随对象一起存放：

  ```
  Base stackObject;             // 对象和 vptr 通常在栈上
  Base* heapObject = new Base;  // 对象和 vptr 通常在堆上
  ```

  虚函数表本身通常不会为每个对象单独创建。

  

- **编译器如何处理虚函数表**

  对于单继承场景，可以粗略理解为：

  1. 派生类继承基类的虚函数入口
  2. 如果派生类重写某个虚函数，对应入口替换为派生类版本
  3. 如果派生类新增虚函数，虚表中增加新的入口


- **构造函数或析构函数中调用虚函数会怎样？**

  在 C++ 里，**构造函数（constructor）和析构函数（destructor）中调用虚函数不会表现出多态**，它只会调用当前类里自己定义的版本，而不会去调用派生类覆盖的版本。

  

  构造 `Derived` 时：

  ```
  Base 构造
  Derived 构造
  ```

  执行 `Base` 构造函数时，`Derived` 部分还没有构造完成，因此调用 `func()` 时执行 `Base::func()`。

  

  析构 `Derived` 时：

  ```
  Derived 析构
  Base 析构
  ```


- **如何获取 虚表地址和虚函数地址？**

  ```c++
  //该类如下：
  class Base {
  public:
      virtual void f() { cout << "Base::f" << endl; }
      virtual void g() { cout << "Base::g" << endl; }
      void h() { cout << "Base::h" << endl; }
  };
  
  Base b;
  
  //  1.&b代表对象b的起始地址
  //  2.(int *)&b 强转成int *类型,为了后面取b对象的前4个字节,前四个字节是虚表指针
  //  3.*(int *)&b 取前四个字节,即vptr虚表地址
  printf("虚表地址:%p\n", *(int *)&b);
  //  根据上面的解析我们知道*(int *)&b是vptr,即虚表指针.并且虚表是存放虚函数指针的
  //  所以虚表中每个元素(虚函数指针)在32位编译器下是4个字节,因此(int *)*(int *)&b
  //  这样强转后为了后面的取四个字节.所以*(int *)*(int *)&b就是虚表的第一个元素.
  printf("第一个虚函数地址:%p\n", *(int *)*(int *)&b);
  printf("第二个虚函数地址:%p\n", *((int *)*(int *)(&b) + 1));
  //始终记着vptr指向的是一块内存,
  //  这块内存存放着虚函数地址,这块内存就是我们所说的虚表.
  //64位下把int换成longlong就好了
  ```



class Derived : public Base
{ 
public: void func() final; 
};

## C++所有构造函数

### 1️⃣ 默认构造函数（Default Constructor）

- **定义**：无参数的构造函数
- **作用**：创建对象时初始化成员，如果没有定义，编译器会自动生成
- **示例**：

```
class A {
public:
    A() { /* 默认初始化 */ }
};

A a; // 调用默认构造函数
```

------

### 2️⃣ 参数化构造函数（Parameterized Constructor）

- **定义**：带参数的构造函数
- **作用**：创建对象时指定初始值
- **示例**：

```
class A {
public:
    A(int x, int y) { /* 使用 x, y 初始化成员 */ }
};

A a(10, 20);
```

------

### 3️⃣ 拷贝构造函数（Copy Constructor）

- **定义**：用一个同类型对象初始化新对象
- **形式**：

```
class A {
public:
    A(const A& other) { /* 拷贝 other 的成员 */ }
};

A a1;
A a2(a1); // 调用拷贝构造函数
```

- **调用场景**：
  - 用对象初始化新对象
  - 函数按值传参
  - 函数按值返回对象
  - 容器插入对象

------

### 4️⃣ 移动构造函数（Move Constructor，C++11 及以上）

- **定义**：用右值对象初始化新对象，避免拷贝开销
- **形式**：

```
class A {
public:
    A(A&& other) noexcept { /* “搬走” other 的资源 */ }
};

A a1;
A a2(std::move(a1)); // 调用移动构造函数
```

- **作用**：
  - 高效管理资源（动态内存、文件句柄等）
  - 常用于临时对象或 `std::move`

------

### 5️⃣ 委托构造函数（Delegating Constructor，C++11）

- **定义**：一个构造函数调用同类的另一个构造函数
- **示例**：

```
class A {
    int x, y;
public:
    A() : A(0, 0) {} // 委托给参数化构造函数
    A(int a, int b) : x(a), y(b) {}
};
```

------

### 6️⃣ 聚合初始化/列表初始化（C++11）

- 用 **花括号 `{}`** 初始化对象
- 可以初始化所有成员（不调用构造函数也可以）

```
struct Point { int x; int y; };
Point p{1, 2};
```

## 什么情况下会调用拷贝构造函数？

1. ## 2️⃣ 调用拷贝构造函数的典型情况

   | 场景                           | 解释                                         | 示例                                 |
   | ------------------------------ | -------------------------------------------- | ------------------------------------ |
   | **用一个对象初始化另一个对象** | 新对象刚创建，用已有对象初始化               | `A a1; A a2(a1);`                    |
   | **按值传参函数**               | 函数参数是对象时，会调用拷贝构造函数拷贝参数 | `void func(A a); func(a1);`          |
   | **按值返回对象**               | 函数返回对象时（按值返回）会调用             | `A func() { return a1; }`            |
   | **容器存储对象**               | STL 容器插入对象时，会拷贝                   | `std::vector<A> v; v.push_back(a1);` |
   | **显示调用**                   | 可以显式调用拷贝构造函数                     | `A a2 = A(a1);`                      |



## 为什么拷贝构造函数必须是引用？

**为了防止递归调用。**

如果不用引用，就会是值传递的方式，但是值传递会调用拷贝构造函数生成临时对象，从而又调用一次拷贝构造函数。就这样无穷的递归下去。

**如果是指针类型**

就变成了一个带参数的构造函数了。。。

比如`A(A* test)`



## 构造函数析构函数是否能抛出异常

### 1. 构造函数

✅ **可以抛出异常**。

- 如果构造函数在执行过程中抛出了异常，对象就算“没构造完成”，所以不会调用它的析构函数（但会对已经构造完成的成员执行析构）。
- 这是 C++ 用来表示“对象创建失败”的方式。

例子：

```
class A {
public:
    A() {
        throw std::runtime_error("构造失败"); // 可以抛异常
    }
};
```

------

### 2. 析构函数

⚠️ **原则上不要抛出异常**。

- C++ 标准允许析构函数内部抛异常，但如果它在“栈展开过程中”再抛异常，会导致 `std::terminate`，程序直接崩溃。
- 所以最佳实践：**析构函数里要么不抛异常，要么捕获并处理掉异常**。

例子：

```
class B {
public:
    ~B() noexcept { // C++11 默认析构函数是 noexcept(true)
        try {
            // 有可能抛异常的代码
            throw std::runtime_error("析构失败");
        } catch (...) {
            // 捕获并处理，不能让它跑出去
        }
    }
};
```



## 创建派生类对象，构造函数的执行顺序是什么？析构函数的执行顺序？

1. 构造和析构顺序是 **对称的**：

   ------

   ### 构造函数执行顺序

   1. **基类构造函数**（从上到下，先父类后子类）
   2. **成员对象的构造函数**（按照类中成员变量的声明顺序，不是初始化列表顺序）
   3. **派生类自身的构造函数体**

   ------

   ### 析构函数执行顺序

   1. **派生类自身的析构函数体**
   2. **成员对象的析构函数**（按照声明顺序的反方向，后声明的先析构）
   3. **基类析构函数**（最后调用）

   ------

   ### 示例代码

   ```
   #include <iostream>
   using namespace std;
   
   class Base {
   public:
       Base() { cout << "Base 构造" << endl; }
       ~Base() { cout << "Base 析构" << endl; }
   };
   
   class Member {
   public:
       Member() { cout << "Member 构造" << endl; }
       ~Member() { cout << "Member 析构" << endl; }
   };
   
   class Derived : public Base {
       Member m;
   public:
       Derived() { cout << "Derived 构造" << endl; }
       ~Derived() { cout << "Derived 析构" << endl; }
   };
   
   int main() {
       Derived d;
       return 0;
   }
   ```

   ### 输出结果

   ```
   Base 构造
   Member 构造
   Derived 构造
   Derived 析构
   Member 析构
   Base 析构
   ```



## C++成员变量的初始化顺序问题成员变量的初始化顺序有几个关键点：

------

### 1. **初始化顺序只跟声明顺序有关**

- 在类里，成员变量会按照它们在**类中声明的顺序**初始化。
- **跟构造函数初始化列表里的书写顺序无关**。

------

### 2. **销毁顺序与构造顺序相反**

- 最后构造的成员，最先析构。

------

### 示例代码

```
#include <iostream>
using namespace std;

class A {
public:
    A(int x) { cout << "A(" << x << ")" << endl; }
};

class B {
public:
    B(int x) { cout << "B(" << x << ")" << endl; }
};

class Test {
    A a;
    B b;
public:
    // 注意：构造函数初始化列表写的顺序是 b, a
    Test() : b(2), a(1) {
        cout << "Test 构造" << endl;
    }
    ~Test() {
        cout << "Test 析构" << endl;
    }
};
 
int main() {
    Test t;
    return 0;
}
```

### 输出结果

```
A(1)   // 先初始化 a（因为它在类里声明在前）
B(2)   // 再初始化 b
Test 构造
Test 析构
B 析构 // b 先析构
A 析构 // a 后析构
```

------

### 3. **规则总结**

- 成员初始化顺序 = **声明顺序**
- 成员析构顺序 = **声明顺序的反向**
- **构造函数初始化列表里写的顺序不会改变初始化顺序**，但可能会引起编译器警告。





## c++的public、private、protected继承特点

假设基类里有三类成员：

```
class Base {
public:
    int pub;       // 公共成员
protected:
    int prot;      // 受保护成员
private:
    int priv;      // 私有成员
};
```

然后用不同的继承方式：

### （1）public 继承

```
class Derived : public Base {};
```

- `Base::pub`  → 在 `Derived` 中还是 **public**
- `Base::prot` → 在 `Derived` 中还是 **protected**
- `Base::priv` → 在 `Derived` 中 **不可见**（继承下来了，但访问不了）

👉 **保持原有权限（除了 private）**

------

### （2）protected 继承

```
class Derived : protected Base {};
```

- `Base::pub`  → 在 `Derived` 中变成 **protected**
- `Base::prot` → 在 `Derived` 中还是 **protected**
- `Base::priv` → **不可见**

👉 **public 变 protected，protected 保持，private 依旧不可见**

------

### （3）private 继承

```
class Derived : private Base {};
```

- `Base::pub`  → 在 `Derived` 中变成 **private**
- `Base::prot` → 在 `Derived` 中变成 **private**
- `Base::priv` → **不可见**

👉 **public / protected 全部变 private，private 依旧不可见**





## 成员初始化列表

### 1. 什么是成员初始化列表？

在构造函数后面用 `:` 的那一段，就是 **成员初始化列表**。

```
class A {
    int x;
    int y;
public:
    A(int a, int b) : x(a), y(b) {   // 这里就是初始化列表
        // 构造函数体
    }
};
```

------

### 2. 为什么要用初始化列表？

有些成员必须用初始化列表，**不能在构造函数体里赋值**：

- **const 成员**

  ```
  class A {
      const int x;
  public:
      A(int a) : x(a) {}   // ✅ 必须在初始化列表里初始化
  };
  ```

- **引用成员**

  ```
  class A {
      int& ref;
  public:
      A(int& r) : ref(r) {}  // ✅ 必须在初始化列表里绑定
  };
  ```

- **没有默认构造函数的成员对象**

  ```
  class B {
      int v;
  public:
      B(int x) : v(x) {}
  };
  
  class A {
      B b;              // b 没有默认构造函数
  public:
      A(int x) : b(x) {}  // ✅ 必须用初始化列表调用 b 的构造函数
  };
  ```

👉 所以初始化列表是 **在对象创建时一次性完成初始化**，而不是先建一个空的再赋值。

------

### 3. 初始化顺序

⚠️ **重点**：初始化顺序只跟成员在类里的声明顺序有关，和初始化列表的书写顺序无关。

```
class A {
    int x;
    int y;
public:
    A(int a, int b) : y(b), x(a) {}  
};
```

虽然写成 `y(b), x(a)`，但会 **先初始化 x，再初始化 y**（因为 `x` 声明在前）。

------

### 4. 使用场景

- 避免重复构造（效率更高）
- 初始化 const、引用成员
- 初始化复杂对象（需要参数的构造函数）



## 谈一谈new/delete和malloc/free的区别和联系（c++管理内存的方式）

- ## 1. 相同点

  - 都是 **动态内存管理**：在堆上申请和释放内存。
  - 都需要开发者手动配对使用，否则会造成内存泄漏。
  - `new` 内部其实通常就是调用了 `malloc` 来分配内存。

  ------

  ## 2. 不同点

  | 对比点            | `new / delete`                                               | `malloc / free`                         |
  | ----------------- | ------------------------------------------------------------ | --------------------------------------- |
  | 所属              | C++ 提供                                                     | C 提供                                  |
  | 返回类型          | 返回指定类型的 **指针**，不需要强制转换                      | 返回 `void*`，在 C++ 中需要强制类型转换 |
  | 内存大小          | 自动根据类型计算所需大小                                     | 需要手动写字节数                        |
  | 是否调用构造/析构 | ✅ 调用构造函数（new），调用析构函数（delete）                | ❌ 只分配/释放内存，不会调用构造/析构    |
  | 重载              | 可以被重载（重载 `operator new`/`operator delete`）          | 不支持重载                              |
  | 分配失败处理      | 默认抛出 `std::bad_alloc` 异常（也可以用 `nothrow` 版本返回 `nullptr`） | 返回 `nullptr`                          |
  | 成对使用          | `new` ↔ `delete`，`new[]` ↔ `delete[]`                       | `malloc` ↔ `free`                       |

  ------

  ## 3. 使用场景举例

  ### （1）使用 `new/delete`

  适合 C++ 对象（需要调用构造和析构）：

  ```
  class A {
  public:
      A() { std::cout << "构造" << std::endl; }
      ~A() { std::cout << "析构" << std::endl; }
  };
  
  int main() {
      A* p = new A;   // 分配内存 + 调用构造函数
      delete p;       // 调用析构函数 + 释放内存
  }
  ```

  输出：

  ```
  构造
  析构
  ```

  ------

  ### （2）使用 `malloc/free`

  只会分配和释放裸内存，不会调用构造/析构：

  ```
  A* p = (A*)malloc(sizeof(A)); // 只分配内存
  free(p);                      // 只释放内存
  ```

  👉 **不会输出构造/析构**。对象根本没被正确构造。

  ------

  ### 4. 联系

  - `new` 本质上：
    1. 调用 `malloc` 分配内存
    2. 在分配的内存上调用构造函数
  - `delete` 本质上：
    1. 调用析构函数
    2. 调用 `free` 释放内存



## 有了malloc/free为什么还要new/delete？

### 1. malloc/free 的问题

`malloc/free` 在 C 里很好用，但放到 C++ 里就有明显缺陷：

1. **不会调用构造函数和析构函数**
   - C++ 对象往往有构造/析构逻辑（比如开文件、开线程、分配资源）。
   - `malloc` 只分配裸内存，不会帮你“建对象”；`free` 也不会帮你“收尾”。
   - 所以用 `malloc/free` 管理 C++ 对象会不安全。
2. **返回类型是 `void\*`**
   - C 里没问题，但在 C++ 里需要强制转换。
   - `new` 会返回正确类型的指针，更安全。
3. **异常机制支持不好**
   - `malloc` 失败返回 `NULL`，程序员容易忘记检查。
   - `new` 失败会抛出 `std::bad_alloc` 异常，更符合 C++ 的错误处理风格。
4. **不支持重载**
   - C++ 可以重载 `operator new` 和 `operator delete`，实现自定义内存池、调试功能。
   - `malloc/free` 是库函数，不能重载。

------

### 2. new/delete 的优势

`new/delete` 是专门为 C++ 设计的：

- **分配内存** + **调用构造函数**
- **调用析构函数** + **释放内存**
- 语法更简洁：`A* p = new A;`（不用写 `sizeof(A)`，不用强转类型）
- 更贴合 C++ 的面向对象设计

------

### 3. 联系

- `new/delete` **内部依旧会调用 malloc/free** 来做“分配和释放内存”的底层工作。
- 它们的区别在于：
  - `malloc/free`：只管“屋子”
  - `new/delete`：管“屋子 + 家具 + 住进去/搬出去”



## new delete，new[] delete[]一定要配对使用吗？为什么？

- 是的，**`new/delete` 和 `new[]/delete[]` 必须配对使用**。原因如下：

  ------

  ### 1. 内存分配机制不同

  - `new` 分配一块内存，只调用一次构造函数；
- `new[]` 会在分配的内存中额外存储“元素个数”，这样在 `delete[]` 时，系统才知道要调用多少次析构函数。
  
  如果你用 `new[]` 分配，却用 `delete` 释放：
  
  - 析构函数只会被调用一次，多出来的对象就没调用析构 → **资源泄漏**。
  - 存储在内存前面的“元素个数信息”可能被错读，导致 **未定义行为**。
  
  ------
  
  ### 2. 析构调用不同
  
  ```
  class A {
  public:
      ~A() { std::cout << "析构" << std::endl; }
  };
  
  int main() {
      A* p1 = new A;       // 单对象
      delete p1;           // ✔ 正确
  
      A* p2 = new A[3];    // 数组对象
      delete[] p2;         // ✔ 正确
  
      // delete p2;       // ❌ 错误：只会调用一次析构
  }
  ```
  
  输出：
  
  ```
  析构
  析构
  析构
  析构
  ```
  
  （第一行是 `p1`，后三行是 `p2` 数组）



## free释放内存的理解

### 1. `free` 是什么

`free` 是 C 标准库里的函数，用来释放之前用 **`malloc/calloc/realloc`** 分配的内存。

```
int* p = (int*)malloc(10 * sizeof(int)); // 分配10个int的空间
free(p); // 释放这块空间
```

------

### 2. 它做了什么

- `malloc` 向堆申请了一块原始内存，返回首地址。
- `free` 把这块内存“交还”给操作系统或内存管理器，告诉它以后可以再用了。

**注意：**

- `free` 只是标记“这块内存不用了”，不会清零内容。

- `free` 也不会自动把指针设成 `NULL`，所以常见习惯是：

  ```
  free(p);
  p = NULL; // 避免野指针
  ```

------

### 3. 和 `delete` 的区别

- `free` 只会释放内存，不会调用对象的析构函数。
- `delete` 先调用析构函数，再释放内存。

```
struct A {
    ~A() { std::cout << "析构" << std::endl; }
};

int main() {
    A* p1 = (A*)malloc(sizeof(A));
    free(p1);     // ❌ 析构函数不会被调用

    A* p2 = new A;
    delete p2;    // ✔ 析构函数被调用
}
```

**被free回收的内存是立即返还给操作系统吗？**

这个需要看源码。

**小块内存**：大多数情况下不会立刻还给操作系统，而是放回进程自己的“堆池子”里，下次 `malloc` 时可以直接复用。这样速度快。

**大块内存**：如果分配特别大，glibc 等库可能直接用 `mmap` 向系统要内存，那么 `free` 时可能真的会调用 `munmap` 归还给操作系统。



## 怎么在栈上分配内存？

### 1. 最常见的方式

直接定义局部变量：

```
void foo() {
    int a = 10;        // 栈上分配4字节
    int arr[100];      // 栈上分配400字节
    // 函数返回时自动销毁
}
```

------

### 2. 动态大小（C99 支持，C++不支持）

```
void bar(int n) {
    int arr[n];  // 栈上分配 n 个 int (变长数组 VLA)
}
```

⚠️ 在 C++ 里不是标准特性（gcc/clang 里可作为扩展）。

------

### 3. 使用 `alloca`（非标准，GNU/MSVC 扩展）

`alloca` 可以在栈上动态分配，函数返回时自动释放：

```
#include <malloc.h>
void foo(int n) {
    int* arr = (int*)alloca(n * sizeof(int)); // 栈上分配
    // 不需要 free，随着 foo() 结束自动回收
}
```

------

### 4. 注意事项

- 栈内存一般有限（几 MB ~ 十几 MB），分配过大会导致 **栈溢出**。
- 栈上内存生命周期短，只能在当前函数里用。返回指针会变成 **野指针**。

```
int* bad() {
    int x = 42;
    return &x;  // ❌ 函数返回后 x 已经销毁
}
```

首先不是BUG，这种情况属于**未定义的行为**，而未定义的行为不会导致编程失败，可能直接把寄存器里的某个值当成返回值

当main函数没有return结尾的时候会在生成的目标文件中自动加入return 0



## c++ 四种强制类型转换

### 1. `static_cast`

**用途**：

- 基本类型之间的转换（int ↔ double）。
- 有继承关系的指针/引用之间的转换（安全的上行转换）。

```
double d = 3.14;
int i = static_cast<int>(d);   // double → int，截断小数

class Base {};
class Derived : public Base {};
Derived* pd = new Derived();
Base* pb = static_cast<Base*>(pd); // 上行转换，安全
```

**特点**：编译期检查，不能去掉 const，不能跨不相关类型。

------

### 2. `dynamic_cast`

**用途**：

- 用于**多态类**（有虚函数）之间的安全向下转型。
- 运行时会检查类型是否正确，失败时返回 `nullptr`（指针）或抛异常（引用）。

```
class Base { public: virtual ~Base(){} };
class Derived : public Base {};

Base* pb = new Derived();
Derived* pd = dynamic_cast<Derived*>(pb); // ✔ 成功

Base* pb2 = new Base();
Derived* pd2 = dynamic_cast<Derived*>(pb2); // ❌ 返回 nullptr
```

**特点**：运行时检查，性能比 `static_cast` 慢。



#### 动态转换是怎么判断这个类型能不能转换为派生类的

基类里必须有 **虚函数**（也就是类型是“多态类”），否则编译报错。
 因为 `dynamic_cast` 要依赖 **RTTI（运行时类型信息）**。



##### 底层判断机制

当你写：

```
Base* b = new Derived();
Derived* d = dynamic_cast<Derived*>(b);
```

编译器实际做了两件事：

1. 每个多态类对象里，都有一个 **vptr**（虚函数表指针），指向对应类的 **vtable**（虚表）。
2. `dynamic_cast` 会去查 RTTI 信息（通常存在 vtable 附近），知道对象真实类型是 `Derived`，所以转换成功，返回指针。

如果对象真实类型是 `Base` 而不是 `Derived`，那 RTTI 检查失败：

- 指针形式 → 返回 `nullptr`
- 引用形式 → 抛出 `std::bad_cast` 异常

------

### 3. `const_cast`

**用途**：

- **去掉/添加 const 或 volatile** 限定。

```
void print(int* p) { *p = 42; }

const int a = 10;
const int* pa = &a;

print(const_cast<int*>(pa)); // 去掉 const
```

⚠️ 如果真的修改了本来是 const 的对象，结果是 **未定义行为**。

------

### 4. `reinterpret_cast`

**用途**：

- 把指针或整数直接按位重新解释，**非常危险**。

```
int a = 65;
char* p = reinterpret_cast<char*>(&a); 
std::cout << *p << std::endl; // 可能打印 'A'，取决于机器字节序
```

**特点**：不做检查，几乎什么都能转，但可能崩溃。

------

### 5. 总结表

| 转换               | 主要用途                   | 安全性                 |
| ------------------ | -------------------------- | ---------------------- |
| `static_cast`      | 基本类型转换、继承关系上行 | 编译期检查，安全       |
| `dynamic_cast`     | 多态类型间向下转型         | 运行时检查，较安全     |
| `const_cast`       | 去/加 const、volatile      | 只能改限定，乱用有风险 |
| `reinterpret_cast` | 重新解释底层比特           | 最危险                 |



## RAII基本理解与使用

> RAII（Resource Acquisition Is Initialization，资源获取即初始化）是 C++ 的一种资源管理惯用法。它利用 **构造函数分配资源、析构函数释放资源**，并依赖 **栈展开时一定会调用析构函数**，从而保证资源始终能被正确释放。



## C++11的enum class 、enum struct 和 enum

- 1. ## 1. 传统 `enum`

     ```
   enum Color { Red, Green, Blue };
     
     int main() {
         Color c = Red;    // ✅ 可以直接用
         int x = Red;      // ❌ 也能编译通过（自动转成 int）
     }
     ```
  
     **特点**：
  
     - 枚举值会暴露在外层作用域（容易冲突）。
     - 枚举值可隐式转成整数（不够类型安全）。
  
     ------
  
     ## 2. `enum class`（C++11 新增）
  
     ```
     enum class Color { Red, Green, Blue };
     
     int main() {
         Color c = Color::Red; // ✅ 必须加作用域
         int x = Color::Red;   // ❌ 编译错误（不能隐式转 int）
     }
     ```
  
     **特点**：
  
     - 枚举值必须用 `作用域限定`（更清晰，不会冲突）。
  
     - 不会隐式转 int（更安全）。
  
     - 可以指定底层类型：
  
       ```
       enum class Color : char { Red, Green, Blue };
       ```
  
     ------
  
     ## 3. `enum struct`
  
     `enum struct` 和 `enum class` **完全一样**，只是语法上提供另一种写法。
  
     ```
     enum struct Color { Red, Green, Blue }; // 等价于 enum class
     ```

##   :watermelon:C++11新特性

[参考链接](https://subingwen.cn/cplusplus/)

### auto和decltype

auto和decltype都是c++11新增的关键字，都用于自动类型推到，但是语法格式有区别。一句话概括，当你需要某个表达式的返回值类型而又不想实际执行它时用decltype。

- **auto**

  auto的出现有对我的代码来说两个作用：

  1. 为了避免太长的类型描述影响代码可读性。比如`std::vector<MyType>::iterator it =  myArray.begin();  `
  2. 这个类型不是我们所关注的，也会用。比如遍历容器中的值，用到

  auto自动帮我们获得定义变量的类型所以auto定义的变量必须有初始值。

  auto可以推断基本类型，也可以推断引用类型，当推断引用类型时候，将引用对象的类型作为推断类型（重要）

  auto的自动类型推断发生在编译期，所以使用auto并不会造成程序运行时效率的降低。

  编译器可以根据初始值自动推导出类型。但是不能用于函数传参以及数组类型的推导

- **decltype**

  一句话概括，当你需要某个表达式的返回值类型而又不想实际执行它时用decltype。

  有时候我们想从表达式中推断出要定义的类型，不会真的求表达式的值。

   `decltype`是为了解决复杂的类型声明而使用的关键字

  1. auto忽略顶层const，decltype保留顶层const；
  2. 对引用操作，auto推断出原有类型，decltype推断出引用；（重要）
  3. 对解引用操作，auto推断出原有类型，decltype推断出引用；
  4. auto推断时会实际执行，decltype不会执行，只做分析。

- **有了auto为什么还需要decltype?**

  `decltype` 可以让你获得编译期的类型。 `auto`不能。所以**当你需要某个表达式的返回值类型而又不想实际执行它时用decltype**。

  ```c++
  int a=8, b=3;
  auto c=a+b; //运行时需要实际执行a+b，哪怕编译时就能推导出类型
  decltype(a+b) d; //编译期类型推导
  //不可以用auto c; 直接声明变量，必须同时初始化。
  ```



### c++智能指针

> 智能指针是一个`RAII`（`Resource Acquisition is initialization`）类模型，用来动态的分配内存。
>
> 把指针用类封装然后实例化成对象，在对象过期的时候，让析构函数删除指向的内存
>
> 它提供所有普通指针提供的接口，却很少发生异常。在构造中，它分配内存，当离开作用域时，它会自动释放已分配的内存。这样的话，程序员就从手动管理动态内存的繁杂任务中解放出来了。

|   指针类别   |     支持     |                 备注                  |
| :----------: | :----------: | :-----------------------------------: |
| `unique_ptr` |    C++ 11    |   拥有独有对象所有权语义的智能指针    |
| `shared_ptr` |    C++ 11    |   拥有共享对象所有权语义的智能指针    |
|  `weak_ptr`  |    C++ 11    | 到 std::shared_ptr 所管理对象的弱引用 |
|  `auto_ptr`  | C++ 17中移除 |   拥有严格对象所有权语义的智能指针    |

#### 为什么要用智能指针？

原因1：内存泄露，即new和delete不匹配

原因2：多线程下对象析构问题，造成这个问题本质的原因是类对象自己销毁(析构)的时候无法对自己加锁,所以要独立出来,采用这个中间层(shared_ptr).

#### auto_ptr

最早的智能指针，c++11之后就删除了，有以下问题：

1. auto_ptr不能指向一组对象，不能和new[]一起使用
2. auto_ptr不能和标准容器一起用
3. 容易野指针。有两个auto_ptr比如说`p1和p2`，当在函数参数见传递指针的时候，所有权也会发生转移。具体来说比如p1指向一块内存，然后p2是p1的拷贝，因此p2也指向了这块内存。当函数调用完后，p2指向的这块内存释放掉了，p1不就成为了一个野指针。

所以这个东西很烂，没什么人用。

#### shared_ptr

**概述**

共享所有权，也就是说多个指针可以指向一个相同的对象，当最后一个shared_ptr离开作用域的时候才会释放掉内存。

实现原理：在shared_ptr内部有一个共享引用计数器来自动管理，计数器实际上就是指向该资源指针的个数，每当复制一个 shared_ptr，引用计数会 + 1。当一个 shared_ptr 离开作用域时，引用计数会 - 1，当引用计数为 0 的时候，则delete 内存。这样相比auto来说就好很多，当计数器为0的时候指针才会彻底释放掉这个资源。



**总结：**shared_ptr智能指针的优势在于一旦某个对象不再被引用，系统会立刻回收内存，通常发生在关键任务完成后的清理时期。同时，内存中所有的对象都是有用的，绝对没有垃圾占内存的现象出现。

#### weak_ptr

`weak_ptr` 比较特殊，它主要是为了配合`shared_ptr`而存在的。就像它的名字一样，它本身是一个弱指针，因为它本身是不能直接调用原生指针的方法的。如果想要使用原生指针的方法，需要将其先转换为一个`shared_ptr`。那`weak_ptr`存在的意义到底是什么呢？

weak指针的出现是为了解决shared指针循环引用造成的内存泄漏的问题。由于`shared_ptr`是通过引用计数来管理原生指针的，那么最大的问题就是循环引用（比如 a 对象持有 b 对象，b 对象持有 a 对象），这样必然会导致内存泄露(无法删除)。而`weak_ptr`不会增加引用计数，因此将循环引用的一方修改为弱引用，可以避免内存泄露。

> 弱指针的使用有两个：第一当 parent 类持有 child 的 shared_ptr, child 持有指向 parent 的 weak_ptr。第二是定义对象时，用强智能指针shared_ptr，在其它地方引用对象时，使用弱智能指针weak_ptr。

#### unique_ptr

`unique_ptr`的核心特点就如它的名字一样，它拥有对持有对象的唯一所有权。即两个`unique_ptr`不能同时指向同一个对象。

那具体这个唯一所有权如何体现呢？

1. `unique_ptr`不能被复制到另外一个`unique_ptr`
2. `unique_ptr`所持有的对象只能通过转移语义将所有权转移到另外一个`unique_ptr`



 **C++ 智能指针的底层实现原理**，包括常用的 `shared_ptr`、`unique_ptr` 和 `weak_ptr`。

------

#### 1. **`unique_ptr`**

- **特点**：独占所有权，不允许拷贝，只能移动（move）。

- **底层实现**：

  ```
  template<typename T>
  class unique_ptr {
      T* ptr; // 真正存储对象的原生指针
  public:
      explicit unique_ptr(T* p = nullptr) : ptr(p) {}
      ~unique_ptr() { delete ptr; }
      
      // 禁止拷贝
      unique_ptr(const unique_ptr&) = delete;
      unique_ptr& operator=(const unique_ptr&) = delete;
      
      // 允许移动
      unique_ptr(unique_ptr&& u) noexcept : ptr(u.ptr) { u.ptr = nullptr; }
      unique_ptr& operator=(unique_ptr&& u) noexcept {
          if (this != &u) {
              delete ptr;
              ptr = u.ptr;
              u.ptr = nullptr;
          }
          return *this;
      }
  
      T& operator*() { return *ptr; }
      T* operator->() { return ptr; }
  };
  ```

- **核心思想**：析构时自动释放资源，只允许一个 `unique_ptr` 拥有对象，防止多重释放。

------

#### 2. **`shared_ptr`**

- **特点**：多个 `shared_ptr` 可以共享同一个对象，引用计数为零时自动释放。

- **底层结构**：

  ```
  template<typename T>
  class shared_ptr {
      T* ptr;             // 真正的对象指针
      size_t* ref_count;  // 引用计数
  public:
      explicit shared_ptr(T* p = nullptr) : ptr(p) {
          if (p) ref_count = new size_t(1);
          else ref_count = nullptr;
      }
      ~shared_ptr() {
          if (ref_count && --(*ref_count) == 0) {
              delete ptr;
              delete ref_count;
          }
      }
  
      // 拷贝构造增加计数
      shared_ptr(const shared_ptr& sp) : ptr(sp.ptr), ref_count(sp.ref_count) {
          if (ref_count) ++(*ref_count);
      }
      // 赋值运算符
      shared_ptr& operator=(const shared_ptr& sp) {
          if (this != &sp) {
              if (ref_count && --(*ref_count) == 0) {
                  delete ptr;
                  delete ref_count;
              }
              ptr = sp.ptr;
              ref_count = sp.ref_count;
              if (ref_count) ++(*ref_count);
          }
          return *this;
      }
  
      T& operator*() { return *ptr; }
      T* operator->() { return ptr; }
  };
  ```

- **核心思想**：

  - 每个 `shared_ptr` 内部维护一个 **引用计数**。
  - 拷贝时计数加 1，析构时计数减 1。
  - 引用计数为 0 → 对象自动销毁。

------

#### 3. **`weak_ptr`**

- **特点**：不增加引用计数，用来观察 `shared_ptr` 指向的对象，避免循环引用。
- **实现原理**：
  - 内部持有一个指向 `shared_ptr` 控制块的指针，但不增加 **strong count**。
  - 可以通过 `.lock()` 获取临时 `shared_ptr`，如果对象已经被销毁，返回空指针。

------

#### 4. **控制块（Control Block）**

- 真正实现 `shared_ptr` 和 `weak_ptr` 的核心是 **控制块（Control Block）**：

  ```
  Control Block:
  ┌─────────────┐
  │ strong_count│ ← shared_ptr 数量
  │ weak_count  │ ← weak_ptr 数量
  │ pointer     │ ← 真正对象的指针
  └─────────────┘
  ```

- **shared_ptr**：

  - 增加/减少 `strong_count`
  - `strong_count = 0` 时 delete 对象
  - `weak_count+strong_count = 0` 时 delete 控制块

- **weak_ptr**：

  - 只增加/减少 `weak_count`
  - 不影响对象生命周期

需要理解的是，智能指针，不管是shared_ptr还是weak_ptr，都会指向一个控制块，控制块里面存放的才是count和对象。shared释放，对象释放了，可是weak还是保留控制块的地址，可以查看里面的信息，只不过不能用这个对象了。



### lambda表达式

我觉得lambda表达式的出现很简洁，也使得代码变得没那么膨胀吧

lambda 表达式定义了一个匿名函数，并且可以捕获一定范围内的变量。lambda 表达式的语法形式简单归纳如下：

```c++
[capture](params) opt -> ret {body;};
```

- 捕获列表 [capture]

  捕获一定范围内的变量，有以下几种方式：

  1. [] - 表示不捕捉任何变量
  2. [&] - 捕获外部作用域中所有变量，并作为引用在函数体内使用 (按引用捕获)
  3. [=] - 捕获外部作用域中所有变量，并作为副本在函数体内使用 (按值捕获)
  4. [=, &foo] - 按值捕获外部作用域中所有变量，并按照引用捕获外部变量 foo
  5. [this] - 捕获当前类中的 this 指针，让 lambda 表达式拥有和当前类成员函数同样的访问权限

  ```c++
  void output(int x, int y)
  {
      auto x1 = [] {return m_number; };                      // error
      auto x2 = [=] {return m_number + x + y; };             // ok
      auto x3 = [&] {return m_number + x + y; };             // ok
      auto x4 = [this] {return m_number; };                  // ok
      auto x5 = [this] {return m_number + x + y; };          // error
      auto x6 = [this, x, y] {return m_number + x + y; };    // ok
      auto x7 = [this] {return m_number++; };                // ok
  }
  ```

- 参数列表 (params): 和普通函数的参数列表一样，如果没有参数参数列表可以省略不写

- opt 选项，不需要可以省略，一般有两个

  1. mutable: 可以修改按值传递进来的拷贝（注意是能修改拷贝，而不是值本身）
  2. exception: 指定函数抛出的异常，如抛出整数类型的异常，可以使用 throw ();

- 返回值类型

  很多时候，lambda 表达式的返回值是非常明显的，因此在 C++11 中允许省略 lambda 表达式的返回值。

- 函数体：函数的实现，这部分不能省略，但函数体可以为空。

### C++11中的原子操作（atomic operation）

在 C++11 中，**原子操作（atomic operation）\**是指对某个变量的操作是\**不可分割的**，在多线程环境下不会被打断，从而保证线程安全。C++11 提供了 `<atomic>` 库来支持。

------

### 1. 为什么需要原子操作

多线程同时访问同一个变量时，如果操作不是原子的，可能出现 **竞态条件（race condition）**：

```
int counter = 0;

void increment() {
    counter++; // 实际是三步：读、加、写，可能被打断
}
```

多个线程同时执行 `counter++`，结果可能比预期小，因为操作被打断。

------

#### 2. `std::atomic` 类型

C++11 提供 `std::atomic<T>` 模板，让操作变成原子操作：

```
#include <atomic>
#include <thread>
#include <iostream>

std::atomic<int> counter(0);

void increment() {
    for (int i = 0; i < 1000; ++i)
        counter++;  // 原子加 1
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);

    t1.join();
    t2.join();

    std::cout << counter << std::endl; // 总是 2000
}
```

------

### 3. 常用原子操作

- `atomic_var++`、`atomic_var--`
- `atomic_var.fetch_add(n)`、`atomic_var.fetch_sub(n)`
- `atomic_var.exchange(new_val)` → 原子交换
- `atomic_var.compare_exchange_strong(expected, desired)` → 原子比较并交换

------

### 4. 内存序（memory order）

- 原子操作可以指定 **内存顺序**，默认 `std::memory_order_seq_cst`（最严格）
- 还可用：
  - `memory_order_relaxed` → 放宽顺序限制
  - `memory_order_acquire/release` → 常用同步模式



### C++11的std::function和std::bind

### 1. `std::function`

### 概念

- `std::function` 是 **可调用对象的类型擦除封装**。
- 它可以存储 **函数、函数指针、lambda、函数对象（仿函数）** 等，统一调用方式。
- 类似于 **C# 的 delegate 或 Java 的 Function**。

### 示例

```
#include <iostream>
#include <functional>

void hello(int x) {
    std::cout << "Hello " << x << std::endl;
}

int main() {
    std::function<void(int)> f = hello; // 保存函数
    f(42); // 调用函数

    auto lambda = [](int x){ std::cout << "Lambda " << x << std::endl; };
    f = lambda; // 可以重新赋值
    f(99); 
}
```

### 特点

- 可以 **存储不同类型的可调用对象**，统一调用接口。
- 支持复制、赋值。
- 有一定开销（类型擦除 + 内存分配），比直接函数指针慢。

------

### 2. `std::bind`

### 概念

- `std::bind` 可以 **绑定函数参数**，生成一个新的可调用对象。
- 可以用于**延迟调用**或**参数重排**。

### 示例

```
#include <iostream>
#include <functional>

void add(int a, int b) {
    std::cout << a + b << std::endl;
}

int main() {
    using namespace std::placeholders; // _1, _2 占位符

    auto f1 = std::bind(add, 10, _1); // 固定第一个参数为 10
    f1(5); // 输出 15

    auto f2 = std::bind(add, _2, _1); // 参数交换
    f2(2, 3); // 输出 5 (3+2)
}
```

### 特点

- 可以固定部分参数，生成新的函数对象。
- 结合 `std::function` 使用，可以**存储、传递、延迟调用**。
- 支持占位符 `_1, _2, ...` 表示调用时传入的参数位置。

------

### 3. `std::function` + `std::bind` 组合

- `bind` 可以生成一个 **统一接口的可调用对象**，存入 `std::function`：

```
std::function<void(int)> f = std::bind(add, 10, _1);
f(5); // 输出 15
```

- 这样可以把复杂函数调用“封装成简单接口”，便于回调、事件处理、线程任务等。

## 实现一个引用计数功能？c++中共享指针是怎样计数的？

> **什么是引用计数？**
>
> 使用一个计数器来标识当前对象被多少指针所指或者被引用的次数。当引用对象被创建或被拷贝时，引用计数要加1；当引用对象被销毁或被覆盖时，引用计数减1；当引用计数为0时，数据对象被销毁。（也是核心原理）。通俗的来讲即这块地址上每多一个指针指向他，计数加一；
>
> 因为有多个指针指向了同一个内存，如果提前释放了这个内存，那其他指向这个地址的指针则会成为野指针，就是指针悬挂现象。同时如果所有的指针都不指向这个地址，这块地址还没被释放，就会被造成内存泄漏。所以采用计数的方式来判断这个地址上还有多少个指针，当最后一个指针不再指向这块内存的时候，就释放掉这块内存。
>
> 
>

**注意千万不要吧一个原生指针给多个共享指针管理，会造成错误，具体看我的注释。**

### C++ `std::shared_ptr` 的计数机制

1. `shared_ptr` 内部维护一个 **控制块（control block）**：
   - **资源指针**：实际对象。
   - **引用计数**：`use_count`，shared_ptr 的数量。
   - **弱引用计数**：`weak_count`，weak_ptr 的数量。
2. 拷贝 `shared_ptr` 时：
   - 计数加 1
3. 销毁或重置时：
   - 计数减 1
   - 当 `use_count == 0`，释放资源
   - 当 `use_count + weak_count == 0`，释放控制块
4. `weak_ptr` 不增加资源引用计数，只增加 weak_count，避免循环引用。
5. 需要理解的是，智能指针，不管是shared_ptr还是weak_ptr，都会指向一个控制块，控制块里面存放的才是count和对象。shared释放，对象释放了，可是weak还是保留控制块的地址，可以查看里面的信息，只不过不能用这个对象了。

## 哈希表时间复杂度为什么是O(1)?

### 1. 哈希表的基本结构

- **数组 + 哈希函数**：

  1. 用一个数组存储数据。
  2. 通过哈希函数 `h(key)` 将键映射成数组下标。
  3. 理想情况下，每个 key 都直接落在一个唯一位置。

- **查找/插入过程**：

  ```
  index = hash(key)     // O(1)
  array[index] = value  // O(1)
  ```

- 理论上，无需遍历，时间复杂度就是 **O(1)**。

------

### 2. 处理冲突（Collision）

哈希冲突不可避免（不同 key 可能映射到同一个 index），常用方法：

1. **拉链法（链表/桶法）**
   - 每个数组位置存一个链表（或动态数组）存储冲突元素。
   - 查找时需要在链表中遍历：
     - 平均长度 ≈ α = n / m（n=元素数，m=桶数）
     - 平均查找 O(1 + α)
   - 当 **负载因子 α 较小**时，仍近似 O(1)
2. **开放寻址法**
   - 冲突元素向数组其他位置探查（线性/二次/双重散列）
   - 平均探查次数在负载因子 α < 1 时常数级别，时间复杂度仍接近 O(1)。

------

### 3. 平均 O(1) vs 最坏 O(n)

- **平均情况**：哈希函数好，冲突少 → O(1)
- **最坏情况**：所有元素都冲突 → 变成链表 → O(n)

> 所以哈希表的 O(1) 是 **平均复杂度**，依赖：
>
> 1. 哈希函数的均匀性
> 2. 桶数量 / 负载因子控制

> **sizeof的定义**

问：定义一个不包含任何成员变量和成员函数的空的类，对该类型sizeof，得到的结果是多少？

答：1。因为该类的实例不包含任何信息，按常理来说应该sizeof=0的。但是当我们声明该类实例时，必须在内存中占用一定的空间才行，否则你无法使用这些实例。

问：如果在空类里面添加一个构造函数和析构函数，sizeof是多少？

答：还是一样的。因为调用构造函数和析构函数或者其他函数只需要知道函数的地址就行，函数的地址和类的实例无关。

问：如果把析构函数或者其他函数编程虚函数呢？

答：如果类中有虚函数，会生成虚函数表，并且每个对象都会在头部添加一个指向虚函数表的指针。所以sizeof就是指针的大小，计算机内部地址总线的宽度，32位机器上是4，64位机器上是8。

问：不用sizeof如何获得int所占的字节数？

思路：设初始值为1，则循环将值左移，直到值为0，记录循环的次数，即总共的位数，再除以8（一个字节=8位），即该类型的字节长度。

```c++
int main()
{
    int i = 1;
    int count = 0;
    while(i)
        i = i <<1;//一个循环，每次左移一位
    	count++;
    cout << count/8 << endl;//因为一个字节8位
    return 0;
}
```



## Volatile的作用？是否具有原子性？对编译器有什么影响？

在 C++ 中，`volatile` 是一个 **类型修饰符**，但很多人容易和原子操作混淆。我们详细分析一下它的作用和限制。

------

### 1. 作用

`volatile` 告诉 **编译器不要优化对该变量的读写**，每次访问都必须从内存中重新读取，而不是使用寄存器缓存。

典型用途：

1. **硬件寄存器**

```
volatile int* REG = (int*)0x4000;
int value = *REG; // 每次都从硬件寄存器读取
```

1. **信号量/中断标志**

```
volatile bool stop = false;

void threadFunc() {
    while(!stop) {
        // do something
    }
}
```

- 如果没有 `volatile`，编译器可能优化成：

  ```
  while(!stop) {} // 假设 stop 不会改变，优化成死循环
  ```

- 加了 `volatile` 后，每次循环都会重新读取 `stop`。

------

### 2. 是否具有原子性？

**不具备原子性**

```
volatile int counter = 0;

counter++; // 不是原子操作，仍然可能被多线程打断
```

- `volatile` 只保证 **不被编译器优化**，**不能保证多个线程访问的安全**。
- 多线程共享变量需要用 **`std::atomic`** 或加锁。

------

### 3. 对编译器的影响

- **禁止优化**：每次访问都必须生成实际内存读写指令。
- **不会生成内存屏障**：`volatile` 不保证 CPU 层面顺序，也不保证可见性跨线程。
- 仅针对 **编译器优化**，不影响硬件缓存或指令重排。

## extern 关键字

①为了能够正确实现C++代码调用其他C语言代码。加上extern "C"后，会指示编译器这部分代码按C语言的进行编译，而不是C++的。主要原因是C++和C程序编译完成后在目标代码中的命名规则不同。比如C++语言在编译的时候为了解决函数的多态问题，会将函数名和参数联合起来生成一个中间的函数名称，而C语言则不会，因此会造成链接时找不到对应函数的情况，此时C函数就需要用extern “C”进行链接指定，这告诉编译器，请保持我的名称，不要给我生成用于链接的中间函数名。

②extern是C/C++语言中表明函数和全局变量作用范围（可见性）的关键字，该关键字告诉编译器，其声明的函数和变量可以在本模块或其它模块中使用。



## auto类型推断的原理



**编译期类型推断**：

- 编译器在编译阶段，检查初始化表达式的类型，然后把 `auto` 替换成对应的具体类型。
- 本质上就是 **语法糖**，最终生成的代码和写明类型一样。

**类似模板类型推导**：

- `auto` 的推导规则和函数模板参数推导类似：

  ```
  template<typename T>
  void foo(T t);
  ```

- 对 `auto var = expr;`，相当于 `T var = expr;` 让编译器推 T。



## C++程序优化的方法

- 空间足够时，可以将经常需要读取的资源，缓存在内存中。
- 尽量减少大内存对象的构造与析构，考虑缓存暂时不用的对象，等待后续继续使用。
- 尽量使用C++11的右值语义，减少临时对象的构造。
- 简单的功能函数可以使用内联。少用继承，多用组合，尽量减少继承层级。
- 在循环遍历时，优化判断条件，减少循环次数。
- 优化线程或进程的同步方式，能用原子操作的就不用锁。能应用层同步的就不用内核对象同步。
- 优化堆内存的使用，如果有内存频繁的申请与释放，可以考虑内存池。
- 优化线程的使用，节省系统资源与切换造成的性能损耗，线程使用频繁的可以考虑线程池。
- 尽量使用事件通知，谨慎使用轮循或者sleep函数。
- 界面开发中，耗时的业务代码不要放在UI线程中执行，使用单独的线程去异步处理耗时业务，提高界面响应速度。
- 经常重构、优化代码结构。优化算法或者架构，从设计层面进行性能的优化。



## void*（泛型指针）

指针是对内存区域的抽象。指针变量中存放着目标对象的内存地址，而与指针相复合的类型，则说明了相应内存区域中的内容具有哪些属性，以及能做什么事情。也就是说，在内存空间某块区域中的内容，原本可以是不可解读的；但是，如果有一个描述这块内存区域的指针存在，我们就能找到它（地址的作用），并且合理地使用它（类型的作用）。void* 只有其中一半的作用。因为没有明确与指针相复合的类型，所以不能解引用，也不能使用基于类型之上（sizeof(T)）的指针运算。



## C++11 RVO/NRVO机制

RVO (return value optimization) 和NRVO (named return value optimization) 是C++在处理 “返回一个class object的函数” 时常用的优化技术，主要作用就是消除临时对象的构造和析构成本。

### 2. RVO（Return Value Optimization）

- **RVO**：返回值优化
- **特点**：
  - 函数返回一个**临时对象**（直接返回 `MyClass()`），编译器可以直接在调用者分配好内存，然后构造对象。
  - 避免调用拷贝/移动构造。

```
MyClass f() {
    return MyClass(); // 临时对象，RVO
}
```

- 优化效果：
  - 编译器直接在调用栈为返回值分配内存
  - 临时对象直接构造到调用者空间 → **零拷贝**

------

### 3. NRVO（Named Return Value Optimization）

- **NRVO**：命名返回值优化
- **特点**：
  - 函数返回一个**命名对象**（如 `obj`），编译器可以将其直接构造到调用者的返回值空间。

```
MyClass f() {
    MyClass obj;  // 命名对象
    // ... 初始化
    return obj;   // NRVO：直接在调用者空间构造 obj
}
```

- 注意：
  - 编译器必须确定返回的是同一个对象
  - 如果存在多个返回路径或对象，可能无法做 NRVO

## C++从源代码到可执行程序的流程是怎样的（c++编译链接过程）

源程序（source code）→预处理器（preprocessor）→编译器（compiler）→汇编程序（assembler）→目标程序（object code）→连接器（链接器，Linker）→可执行程序（executables）

  - **工具**：C++ 预处理器（通常是 `cpp`）
  - **作用**：
    1. 处理 `#include` 指令 → 把头文件内容插入源文件
    2. 处理宏 `#define`
    3. 条件编译 `#if/#ifdef`
    4. 删除注释
  - **结果**：生成 **纯 C++ 代码文件**，所有宏和头文件已经展开

  ```
  #include <iostream>
  #define PI 3.14
  ```

  会被替换为：

  ```

  // 宏 PI 替换为 3.14
  ```

  ------

  ## 2. 编译（Compilation）

  - **工具**：C++ 编译器（如 `g++` 或 `clang++`）
  - **作用**：
    1. 语法检查
    2. 类型检查
    3. 模板实例化
    4. 将 C++ 源代码翻译为 **汇编代码**
  - **结果**：生成 **汇编文件**（.s）

  ------

  ## 3. 汇编（Assembly）

  - **工具**：汇编器（Assembler）
  - **作用**：
    - 将汇编代码转成 **机器码指令**
    - 分配寄存器、生成指令序列
  - **结果**：生成 **目标文件（.o 或 .obj）**
    - 里面包含机器码，但还没有链接其他模块

  ------

  ## 4. 链接（Linking）

  - **工具**：链接器（Linker）
  - **作用**：

    2. 解析外部符号（函数/全局变量）
    3. 链接标准库、第三方库
    4. 分配最终的内存地址（重定位）
  - **结果**：生成 **可执行程序**（如 `.exe` 或 Linux 下的无扩展名文件）

  ------

  ## 5. 加载与运行（Load & Execution）

  - **过程**：
    1. 操作系统将可执行文件加载到内存
    2. 分配栈、堆空间
    3. 初始化全局变量
    4. 调用 `main()` 函数开始执行

## C++的静态链接和动态链接讲一下

### 1. 静态链接（Static Linking）

### 特点

- 编译时把库的代码 **直接复制到可执行文件** 中
- 最终生成的可执行文件 **自包含**，不依赖外部库
- 链接后，库的修改不会影响程序运行

### 优点

1. 可执行文件独立，方便分发
2. 启动速度快，不依赖外部库

### 缺点

1. 文件体积大（库代码嵌入）
2. 更新库需要重新编译程序

### 示例

```
g++ main.cpp libfoo.a -o myprog  # libfoo.a 是静态库
```

------

### 2. 动态链接（Dynamic Linking）

### 特点

- 可执行文件在 **运行时** 再加载库（.so / .dll）
- 可执行文件中只包含 **库的引用**，不包含库代码
- 库可以被多个程序共享

### 优点

1. 文件体积小
2. 库更新无需重新编译程序
3. 内存共享，提高系统效率

### 缺点

1. 运行依赖库文件（可能出现“找不到 DLL/so”问题）
2. 启动速度略慢





## 指针没有初始化会怎么样

没有初始化的指针叫做野指针

指针未初始化能通过编译，但是运行的时候可能报错也可能不报错。因为你如果没使用这个指针，那倒是无所谓。但是如果你使用了，可能会出问题。因为这个指针由于没有初始化，可能会指向任何内存空间，完全随机的，有两种情况：

1. 指向的地址是系统使用的内存，用户程序不能使用，如果用户程序使用则会报错
2. 指向的不是系统的内存，不报错。但是如果这个指针指向了你之前程序使用过的内存，则你在个指针赋值，就会修改之前的内存上的数据，也会出问题。

指针变量设置为nullptr表明它不指向任何内容,这样引用她也不会出现上面的问题。

**空指针到底是什么？**

 由系统保证空指针不指向任何实际的对象或函数，也就是说，任何对象或者函数的地址都不可能是空指针，空指针与任何对象或函数的指针值都不相等。空指针表示“未分配”或者“尚未指向任何地方”。它与未初始化的指针有所不同，空指针可以确保不指向任何对象或函数，而未初始化指针可能指向任何地方。



## 野指针和指针悬挂

野指针(wild pointer)指的是未经初始化的指针

悬挂指针(dangling pointer)指的是已经销毁的对象或已经回收的地址



## 基础变量没有初始化怎么样

不怎么样，不使用他就行。

建议变量在构造函数时均初始化完成，避免不必要的问题。比如变量char buf[2000]，把字符串"hello world"拷贝进入buf，恰好EOF("\0")没有被复制，由于没有使用memset初始化变量，buf空间时随机值,那么调用print，strcmp之类的操作时，有可能会因为没有EOF,导致访问到非法地址，然后程序异常。



## c/c++参数入栈顺序和参数计算顺序

**c/c++中规定了函数参数的压栈顺序是从右至左**

举个例子：

```c++
void fun(int x, int y, int z)
{
    cout << x << &x << endl;
    cout << y << &y << endl;
    cout << z << &z << endl;
}

int main(int argc, char *argv[])
{
    fun(1, 2, 3);
    system("pause");
    return 0;
}
```

输出如下：

我们知道先入栈的占高地址，从结果看出入栈的顺序依次为`z->y->x`，即压栈顺序从右至左。

**why?**

本质上是因为支持可变长参数导致的。如果是从左至右的入站方式，最左边的参数就会被压在栈底，栈顶指针指向的是最右边的长度参数，由于可变长度，编译器无法找到最左边的参数吧。但是如果从右至左入栈，最左边的参数就在栈顶。





## 模板元编程

C++ 模板实现 **编译期的泛型编程**，可以生成一组类型或函数。主要分为 **函数模板** 和 **类模板**。

------

### 1. 模板概念

- **声明语法**：

```
template <typename T>  // 或 template<class T>
```

- T 可以是基本类型、类类型，模板参数可以多个：

```
template <typename T1, typename T2>
```

- **泛型编程**：通过模板让代码可复用、适用于多种数据类型。

------

### 2. 模板底层实现原理

1. **模板本身不生成代码**，只有实例化时才生成具体函数或类。
2. **两次编译**：
   - 声明处编译模板代码本身
   - 调用处用具体类型实例化模板，再编译成真正的函数/类
3. **模板必须定义在头文件**，否则链接会报错（编译单元独立，实例化失败）。

------

### 3. 函数模板

- **调用方式**：

  1. **自动类型推导**（隐式）

     ```
     mySwap(a, b);
     ```

  2. **显式指定类型**

     ```
     mySwap<int>(a, b);
     ```

- **注意事项**：

  - 自动推导时，所有参数类型必须一致
  - 模板必须能确定出类型 T

- **与普通函数的区别**：

  | 特性         | 普通函数 | 函数模板                           |
  | ------------ | -------- | ---------------------------------- |
  | 自动类型转换 | 可发生   | 自动推导不发生，显式指定可发生     |
  | 调用优先级   | 优先调用 | 可通过空模板参数 `<>` 强制调用模板 |
  | 重载         | 支持     | 支持，优先匹配更好类型             |

------

### 4. 类模板

- **特点**：

  - 无自动类型推导，必须显式指定类型参数：

    ```
    Person<int, std::string> p;
    ```

  - 成员函数在调用时才实例化

  - 成员函数模板不能是 `virtual`（虚表大小在类解析时必须确定）

- **类模板成员函数类外实现**：

```
template<class T1, class T2>
Person<T1,T2>::Person(T1 name, T2 age) {}

template<class T1, class T2>
void Person<T1,T2>::show() {}
```

------

### 4.1 类模板对象作为函数参数

1. **指定类型**

```
void print(Person<std::string, int>& p);
```

1. **模板化参数**

```
template<class T1, class T2>
void print(Person<T1,T2>& p);
```

1. **整个对象模板化**

```
template<class T>
void print(T& p);
```

------

### 4.2 类模板与继承

1. **子类继承类模板**，必须指定父类类型：

```
template<class T>
class Father { T m; };

class Son : public Father<int> {};  // 正确
```

1. **灵活继承**：

```
template<class T1, class T2>
class Son : public Father<T2> { T1 obj; };
```

------

### 5. 模板与实现分离问题

- **原因**：
  - 模板在编译时不生成代码，只有实例化时才生成
  - 如果函数模板定义在 cpp 文件，main.cpp 编译时无法实例化 → 链接失败
- **解决办法**：模板声明和定义都放在头文件。

------

### 6. 模板函数 vs 类模板

| 特性       | 函数模板         | 类模板                 |
| ---------- | ---------------- | ---------------------- |
| 实例化时间 | 编译器自动实例化 | 需要显式指定类型       |
| 调用方式   | 隐式/显式都可    | 只能显式指定类型 `<T>` |
| 多态性     | 编译时多态       | 编译时多态             |

------

### 7. 模板 vs 继承

| 特性     | 模板               | 继承                       |
| -------- | ------------------ | -------------------------- |
| 多态性   | 编译时             | 运行时                     |
| 作用     | 生成多组类型/函数  | 从共性到特性（父类到子类） |
| 实现方式 | 代码复制（实例化） | 虚表 + 数据复制            |



## mutable关键字

在 C++ 中，`mutable` 是一个修饰 **类成员变量** 的关键字，它允许 **即使在 `const` 对象中，也可以修改这个成员变量**。

------

### 1. 基本用法

```
class Example {
public:
    mutable int counter;  // 可在 const 对象中修改

    Example() : counter(0) {}

    void increment() const {  // const 成员函数
        counter++;  // 可以修改，因为 counter 是 mutable
    }
};

int main() {
    const Example e;
    e.increment();  // OK
}
```

- `const Example e;` → 对象是不可修改的
- 普通成员变量在 const 成员函数或 const 对象中 **不能修改**
- `mutable` 修饰的成员变量可以被修改

------

### 2. 使用场景

1. **缓存/统计信息**
   - 对象逻辑上不变，但内部需要记录访问次数或缓存

```
class Data {
    mutable int access_count;
public:
    int getValue() const {
        access_count++;  // 不违反逻辑 const
        return 42;
    }
};
```

1. **调试/日志**
   - 即使对象是 const，也可以更新调试或日志信息

------

### 3. 注意事项

- 只影响成员变量的修改权限，不影响线程安全
- 不能用于全局变量或局部变量
- 与 `const` 成员函数配合使用最常见







## 虚继承

**为什么要引入虚拟继承**

虚拟继承是多重继承中特有的概念。虚拟基类是为解决多重继承而出现的。如:类D继承自类B1、B2，而类B1、B2都继承自类A，因此在类D中两次出现类A中的变量和函数。实现的代码如下：

class A

class B1:public virtual A;

class B2:public virtual A;

class D:public B1,public B2;

上述就是菱形继承会产生两个问题。首先是空间问题，不节省空间。类B中有类A的数据，类C中也有。其次是二义性，歧义问题。当类D调用类A中的数据时候，到底是走类B的还是走类D的？如下：

```c++

void seta(int a){ C::m_a = a; }	// C类中的m_a
```

虚拟继承在一般的应用中很少用到，所以也往往被忽视，这也主要是因为在C++中，多重继承是不推荐的，也并不常用，而一旦离开了多重继承，虚拟继承就完全失去了存在的必要因为这样只会降低效率和占用更多的空间。

## C++编译期多态与运行期多态

**编译期多态**

又叫做静态多态。指的是c++的泛型编程中（引申出泛型编程）模板的具现化与函数的重载解析。

编译期多态的类之间没有继承关系，约束他们的是相似的接口。在编译期间，编译器推断出模板参数，因此确定调用函数是哪个具体类型的接口。不同的推断结果调用不同的函数，这就是编译器多态。这类似于重载函数在编译器进行推导，以确定哪一个函数被调用。

**运行期多态**

又叫做动态多态。指的是c++面向对象编程中的三大特性之一。（引申出虚函数）

运行期多态要归结于类的继承思想。对于有相关功能的对象集合，我们总希望能够抽象出它们共有的功能集合，在基类中将这些功能声明为虚接口（虚函数），然后由子类继承基类去重写这些虚接口，以实现子类特有的具体功能。

运行期多态的实现依赖于虚函数机制。当某个类声明了虚函数时，编译器将为该类对象安插一个虚函数表指针，并为该类设置一张唯一的虚函数表，虚函数表中存放的是该类虚函数地址。运行期间通过虚函数表指针与虚函数表去确定该类虚函数的真正实现。

**运行期多态与编译期多态优缺点分析**

- 运行期多态优点
  1. 灵活
  2. 方便程序耦合同时减少内聚
  3. 能够处理异质对象集合（一个动物园有一堆动物，每一种动物都是一个对象）
- 运行期多态缺点
  1. 运行期间进行虚函数绑定，提高了程序运行开销。
  2. 庞大的类继承层次，对接口的修改易影响类继承层次。
  3. 由于虚函数在运行期在确定，所以编译器无法对虚函数进行优化。
- 编译期多态优点
  1. 它带来了泛型编程的概念，使得C++拥有泛型编程与STL这样的强大武器。
  2. 在编译器完成多态，提高运行期效率。
  3. 具有很强的适配性与松耦合性，对于特殊类型可由模板偏特化、全特化来处理。
- 编译期多态缺点
  1. 程序可读性降低，代码调试带来困难。
  2. 无法实现模板的分离编译，当工程很大时，编译时间不可小觑。
  3. 无法处理异质对象集合。





## C++ 中的指针参数传递和引用参数传递

### 1. 指针参数传递

### 特点

- 传递的是变量的地址（内存位置）
- 函数内可以修改指针指向的值
- 调用时需要取地址 `&`

### 示例

```
void increment(int* p) {
    (*p)++;  // 修改指针指向的值
}

int main() {
    int a = 10;
    increment(&a);  // 传地址
    // a = 11
}
```

### 注意

- 指针可以为 `nullptr` → 调用前需检查
- 可以修改指针本身（让它指向别的地址），但这种修改不会影响调用者传入的原指针（除非传递的是指向指针的指针）

------

### 2. 引用参数传递

### 特点

- 传递的是变量的别名（alias）
- 函数内修改引用，就是修改原变量
- 使用时像普通变量，不需要取地址

### 示例

```
void increment(int& r) {
    r++;  // 直接修改原变量
}

int main() {
    int a = 10;
    increment(a);  // 不需要 &
    // a = 11
}
```

### 注意

- 引用必须初始化
- 引用不能为 `nullptr`（必须引用一个已有变量）

## 函数指针（Function Pointer）

### 1. 定义

- 函数指针是一个 **指针变量**，指向函数的 **入口地址**
- 有了函数指针后，可以通过它 **调用对应函数**

```
int add(int a, int b) { return a + b; }

// 定义函数指针
int (*funcPtr)(int, int) = add;

// 通过指针调用函数
int result = funcPtr(2, 3);  // result = 5
```

### 2. 用途

1. **调用函数**（间接调用）
2. **作为参数传递**（回调函数）
3. 实现 **多态或策略模式**（运行时选择不同函数）

------

通俗理解：

- **普通指针**指向变量
- **函数指针**指向函数，让你通过变量调用函数

## C++异常处理的方法

## C++函数调用的压栈过程

当函数从入口函数main函数开始执行时，编译器会将我们操作系统的运行状态，main函数的返回地址、main的参数、mian函数中的变量、进行依次压栈；

当main函数开始调用func()函数时，编译器此时会将main函数的运行状态进行压栈，再将func()函数的返回地址、func()函数的参数从右到左、func()定义变量依次压栈；当func()调用f()的时候，编译器此时会将func()函数的运行状态进行压栈，再将的返回地址、f()函数的参数从右到左、f()定义变量依次压栈

## 怎样判断两个浮点数是否相等？

在 C++ 中，直接用 `==` 比较两个浮点数通常不可靠，因为浮点数存在 **精度误差**（如二进制表示无法精确表示某些小数）。正确做法是判断 **差值是否足够小**。

对于两个浮点数比较只能通过相减并与预先设定的精度比较，记得要取绝对值！浮点数与0的比较也应该注意。与浮点数的表示方式有关



```
#include <cmath>

bool isEqual(double a, double b, double epsilon = 1e-9) {
    return std::fabs(a - b) < epsilon;
}
```

- `epsilon` 表示允许的误差范围
- `fabs(a - b) < epsilon` 表示 a 和 b 足够接近，可视为相等

#include <cmath>

## C++为什么提供move函数？

### 1. 背景

- 传统 C++ 拷贝语义（copy）会**复制资源**，开销大

  ```
  std::vector<int> v1 = {1,2,3,4};
  std::vector<int> v2 = v1;  // 复制整个数组，开销大
  ```

- 对于临时对象或即将销毁的对象，复制资源是浪费

------

### 2. 移动语义

- **移动** = **资源“搬走”**而不是复制
- 使用 `std::move` 将对象转换为 **右值引用**，允许资源被“窃取”而不是复制

```
#include <vector>
#include <utility> // std::move
#include <iostream>

int main() {
    std::vector<int> v1 = {1,2,3,4};
    std::vector<int> v2 = std::move(v1); // v1的资源直接给v2，v1变空
}
```

- `v2` 直接获得 `v1` 的内存指针，避免逐元素复制
- `v1` 仍然有效，但内容已被移动

------

### 3. 适用场景

1. **返回局部对象**

   ```
   std::vector<int> createVector() {
       std::vector<int> v = {1,2,3};
       return std::move(v);  // 避免复制
   }
   ```

2. **大对象赋值**

3. **标准容器插入或重排元素**

------

### 4. 总结

- `std::move` 并不移动数据，只是将左值 **标记为右值引用**
- 移动语义减少不必要的深拷贝，提升性能
- 搭配 **移动构造函数** 或 **移动赋值运算符** 使用

## 如何在类的内部返回一个指向自己的智能指针

在类的内部直接写 `return shared_ptr<MyClass>(this);` 是 **错误的**，因为：

- 这个return重新调用了shared_ptr方法，会创建一个新的 `shared_ptr`，它的控制块和外部 `shared_ptr` 不是同一个，这时候同一个对象就有两个shared_ptr来管理了。
- 同一个对象被两个 `shared_ptr` 管理，等用完了，最终会 **析构两次，出现错误**。

------

### ✅ 正确做法：用 `enable_shared_from_this`

标准库里有一个工具类 `std::enable_shared_from_this<T>`，专门解决这个问题。

### 示例：

```
#include <iostream>
#include <memory>
using namespace std;

class MyClass : public enable_shared_from_this<MyClass> {
public:
    shared_ptr<MyClass> getPtr() {
        // 正确获取自己对应的 shared_ptr
        return shared_from_this();
    }

    void hello() {
        cout << "Hello from MyClass\n";
    }
};

int main() {
    // 必须用 shared_ptr 创建对象
    auto p1 = make_shared<MyClass>();

    auto p2 = p1->getPtr();  // p2 和 p1 共享同一个控制块
    cout << "use_count = " << p1.use_count() << endl;

    p2->hello();
}
```

### 输出：

```
use_count = 2
Hello from MyClass
```

------

### ⚠ 注意事项

1. 对象必须是由 **`shared_ptr` 管理创建的**，比如 `make_shared`。
    如果你写 `MyClass obj; obj.getPtr();` 会崩溃。
2. `shared_from_this()` 返回的 `shared_ptr` 与外部的是同一个控制块，引用计数正确。
3. 如果你真的需要裸指针 `this`，也可以用，但必须小心不要再去生成新的 `shared_ptr(this)`。





## 如何解决不同编译单元间 static 变量析构顺序不一致的问题？ C++ 中是否有语言特性可以解决上述析构顺序问题？

### 2. 常见解决办法

#### (1) **避免跨单元静态变量依赖**

👉 最根本的解决方式就是 **不要设计这种依赖**。

------

#### (2) **局部静态变量（Meyers Singleton 技巧）**

利用 **函数内的 `static` 变量**：

- 构造在第一次调用时发生
- 析构在 `main` 退出时由编译器保证
- **C++11 以后保证了线程安全初始化**

```
class Config {
public:
    static Config& instance() {
        static Config cfg;  // 局部静态对象
        return cfg;
    }
};
```

这样就能保证构造和析构顺序不依赖其他编译单元。

------

#### (3) **故意不析构**

如果全局对象是“程序运行期间常驻”的（比如日志系统、内存池）：

- 可以用 `new` 出来，不写 `delete`，让操作系统在进程结束时统一回收。
- 或者用 `atexit()` 注册析构，但这又引入了顺序问题。

------

#### (4) **使用智能指针和显式生命周期管理**

例如 `std::shared_ptr` 或者手动控制初始化/清理时机。
 不过这就要求你明确在 `main` 里安排资源释放，不再依赖静态变量析构。

------

### 3. C++ 语言特性支持

C++ 本身没有提供“保证跨编译单元静态变量析构顺序”的机制。
 但 C++11 之后提供了一个关键特性，能帮我们避免：

- **局部静态变量延迟初始化（magic statics）**：
   保证了函数内静态变量只在首次调用时构造，且线程安全。
   这就是推荐的替代方案（Meyers Singleton）。



## 如果在头文件中定义一个 static 变量，会发生什么？

### ✅ 总结

- **头文件里的 `static` 全局变量** → 每个 `.cpp` 一份，互不干扰。
- **头文件里的 `static` 局部变量 (magic static)** → 可以用，且只有一份（C++11 起安全）。
- **头文件里的 `static` 成员变量定义** → 错误，容易重复定义。



## 在函数中声明一个对象但不初始化，会有什么问题？（针对基本类型）

在函数中声明一个 **基本类型对象但不初始化**，会有 **未定义行为 (Undefined Behavior, UB)** 的风险。

------

### 📌 例子：

```
void foo() {
    int x;   // 只声明，没有初始化
    std::cout << x << std::endl; // ❌ 未定义行为
}
```

### 原因：

- **局部变量（自动存储期）** 默认不会被初始化。
- 它的内存里可能是**栈上残留的数据**（上一次函数调用、别的变量的数据）。
- 读取未初始化的值 → **未定义行为**：可能是任意数值，甚至可能导致程序异常。

------

### 📌 和全局变量对比：

```
int g; // 全局变量，默认初始化为 0
```

- **全局/静态存储期变量** 会 **自动初始化为 0**。
- **局部变量** 不会初始化，必须手动赋值。

------

### ✅ 正确做法：

```
void foo() {
    int x = 0;  // ✅ 显式初始化
    std::cout << x << std::endl;
}
```



## 为什么函数内的局部变量（基本类型）如果不初始化，其值是不确定的？

**自动存储期（函数内的局部变量，普通基本类型）**
 编译器只在栈上 **为它分配一块内存空间**，但 **不会清零或赋初值**。
 → 这块内存里可能残留着之前别的函数调用、局部变量留下的随机数据。
 → 所以值是“不确定的”。



### 📌 那为什么 **全局变量 / 静态变量** 不会这样？

- 全局/静态变量存放在 **静态存储区**。

- C++ 标准规定：如果没有显式初始化，会 **默认初始化为 0**（或相应的默认值）。

  ```
  static int x; // 自动初始化为 0
  int g;        // 全局变量，也初始化为 0
  ```



## 基本数据类型（如 int）是否可以通过 move 操作移动到堆上？

很关键的一点：**C++ 的 `std::move` 并不会把对象从栈搬到堆**。
 它只是一个“类型转换工具”，告诉编译器“我愿意把这个对象当右值对待，可以调用它的移动构造/移动赋值”。

------

### 1. 基本类型（int、double 等）

```
int a = 42;
int b = std::move(a);
```

- `std::move(a)` 只是把 `a` 转成右值引用类型（`int&&`）。
- 但是 **int 没有移动构造函数**，所以效果和普通拷贝一模一样。
- 也就是说，`b = a`，`a` 还是 42，不会“空掉”。

👉 **结论**：基本类型没有 move 语义，std::move 对它们不起作用。

------

### 2. 把基本类型放到堆上

如果你真的想要 `int` 在堆上存储，只能手动 `new`：

```
int a = 42;
int* p = new int(std::move(a));  // 堆上创建一个 int，拷贝 a 的值
```

这里 `std::move(a)` 没任何特殊效果，还是拷贝 42 到堆上。

------

### 3. 为什么类类型可以“move”？

```
std::string s1 = "hello";
std::string s2 = std::move(s1);
```

- 这里 `std::move` 让编译器调用 **string 的移动构造函数**。
- 内部实现是“偷指针”：s2 接管 s1 的堆内存，s1 被置空。
- 所以移动有效率意义。

------

✅ **总结**

- **基本类型（int, double, char …）没有移动语义**，std::move 不会让它们“移动到堆上”。
- 想放堆上只能 `new`，但这只是复制到堆，而不是“移动”。
- 移动语义只对有资源（比如堆内存、文件句柄）的类有意义。



## `const` 和 `constexpr` 有什么区别？

### 1. 正确解释

- **`const`**

  - 表示 **只读**（不可修改），但它的值是否在编译期就确定 **不保证**。

  - 可以是 **运行时** 才确定的值。

  - 例子：

    ```
    const int a = 10;    // 编译期已知
    int x = 5;
    const int b = x;     // 运行时才能确定
    ```

- **`constexpr`**

  - 表示这个变量或函数的值 **必须能在编译期计算出来**（如果上下文要求）。

  - 一定是 **常量表达式**。

  - 用于需要编译期常量的场合（比如数组大小、模板参数）。

  - 例子：

    ```
    constexpr int c = 10;    // 编译期常量
    // constexpr int d = x;  // 错误：x 是运行时变量
    ```

------

### 2. 用很简单的话说

- `const`：这个变量 **不能改**，但值可能是程序运行时才知道的。
- `constexpr`：这个变量 **不仅不能改，而且值在编译时就必须确定**。



## 能介绍一下什么是“完美转发”（Perfect Forwarding）吗？

完美转发”是 **C++11 引入的一个很高级但非常实用的技巧**，它主要用来 **在模板里把参数完全按照原来的类型传递下去**，包括左值/右值属性。主要原因是右值也不是变量，作为一个值传进去一个函数，就用这一次，可是如果被当成左值来看待，后面用的时候就还会被初始化，执行构造，占用资源。如果传进去的时候就一直当成右值来看待，那么走到最后用的时候，就直接把这个右值的全部资源move掉，避免了多余的拷贝。

------

### 1. 背景问题

假设你写一个函数模板包装另一个函数：

```
void foo(int& x) { std::cout << "lvalue\n"; }
void foo(int&& x) { std::cout << "rvalue\n"; }

template<typename T>
void wrapper(T t) {
    foo(t); // ❌ 这里 t 总是被当作左值传递
}
```

- 你会发现：**无论传入左值还是右值，`foo(t)` 都会调用 `foo(int&)`**，因为 `t` 在模板里是一个命名变量，总是左值。

> 问题原因：模板里变量是命名变量 → 都是左值。

------

### 2. 完美转发的核心工具

- **转发引用（Universal/Forwarding Reference）**

  ```
  template<typename T>
  void wrapper(T&& t) { ... }
  ```

  当 `T&&` 出现在模板参数里时，它既能绑定左值也能绑定右值。

- **`std::forward<T>`**
   可以把参数的左值/右值属性保留下去，传递给另一个函数。

------

### 3. 完美转发示例

```
#include <iostream>
#include <utility>
using namespace std;

void foo(int& x)  { cout << "lvalue\n"; }
void foo(int&& x) { cout << "rvalue\n"; }

template<typename T>
void wrapper(T&& t) {
    foo(std::forward<T>(t)); // ✅ 完美转发
}

int main() {
    int a = 10;
    wrapper(a);          // 调用 foo(int&) -> 输出 lvalue
    wrapper(20);         // 调用 foo(int&&) -> 输出 rvalue
}
```

- `std::forward<T>(t)` 根据 `T` 的类型决定是左值引用还是右值引用
- 所以 `wrapper` 就 **完美保留了原来的值类别**





------

### 4. 总结

- **完美转发** = 把参数 **完全按照原来的属性（左值/右值）传下去**
- **用法**：
  1. 模板参数用 `T&&`（转发引用）
  2. 调用时用 `std::forward<T>(t)`
- 解决了普通模板转发中 **右值被当作左值的问题**



##  如何实现一个参数数量和类型都不固定的函数？

在 C++ 中，如果你想实现一个 **参数数量和类型都不固定的函数**，有几种方法，取决于你要用的是 **C 风格** 还是 **C++ 风格**。

------

### 1. **C 风格可变参数 (`...`)**

```
#include <cstdarg>
#include <iostream>
using namespace std;

void printAll(int count, ...) {
    va_list args;           // 定义可变参数列表
    va_start(args, count);  // 初始化
    for (int i = 0; i < count; ++i) {
        int val = va_arg(args, int); // 取出一个参数，必须指定类型
        cout << val << " ";
    }
    va_end(args);           // 清理
    cout << endl;
}

int main() {
    printAll(3, 1, 2, 3);  // 输出 1 2 3
}
```

- **优点**：可以接受任意数量的参数。
- **缺点**：类型不安全，每次必须手动指定类型（`va_arg(args, int)`），容易出错。

------

### 2. **C++11 可变模板参数（推荐）**

```
#include <iostream>
using namespace std;

template<typename... Args>
void printAll(Args... args) {
    (cout << ... << args) << endl; // 折叠表达式，C++17
}

int main() {
    printAll(1, 2.5, "hello"); // 输出 12.5hello
}
```

- `Args...` 表示 **任意数量任意类型** 的模板参数
- `(cout << ... << args)` 是 **折叠表达式**（C++17）
- **类型安全**，无需手动转换

> 如果使用 C++11/14，可以用递归展开模板：

```
template<typename T>
void print(T t) { cout << t; }

template<typename T, typename... Rest>
void print(T t, Rest... rest) {
    cout << t;
    print(rest...);
}
```

## 栈溢出解决方法

栈溢出（Stack Overflow）通常是 **函数调用或局部变量占用过多栈空间** 导致的。解决思路主要从 **减少栈空间使用** 和 **优化递归/调用** 两方面入手。

------

### 1. **减少局部变量栈占用**

- 大数组、大对象不要放在栈上，改为 **堆分配**：

```
void foo() {
    // int arr[100000]; // 栈上大数组，可能溢出
    int* arr = new int[100000]; // 堆上
    delete[] arr;
}
```

- 对象也可以用 `std::unique_ptr`、`std::vector` 管理：

```
std::vector<int> vec(100000); // 堆上
```

------

### 2. **优化递归**

- 递归深度过大容易栈溢出。

- 方法：

  1. **改成迭代**：

     ```
     // 递归求阶乘 → 改成循环
     int fact(int n) {
         int res = 1;
         for (int i = 2; i <= n; ++i) res *= i;
         return res;
     }
     ```

  2. **尾递归优化**（某些编译器支持）：

     ```
     int factTail(int n, int acc=1) {
         return n==0 ? acc : factTail(n-1, n*acc);
     }
     ```

------

### 3. **增加栈空间**

- 系统允许的话，可以通过 **修改线程栈大小** 增大栈：
  - Linux: `ulimit -s` 或 `pthread_attr_setstacksize`
  - Windows: 修改编译选项 / `CreateThread` 的栈大小参数

> 但是这种方法只是缓解，不解决根本问题，根本问题是函数或局部变量占用过多栈。

------

### 4. **避免循环引用导致隐性递归**

- C++ 中智能指针循环引用不会直接导致栈溢出，但如果你写递归析构函数，可能间接导致：

```
struct Node {
    std::shared_ptr<Node> next;
    ~Node() { std::cout << "destroy\n"; } // 如果递归调用可能爆栈
};
```

- 使用 `weak_ptr` 或手动打断链表可以避免。

------

### ✅ 总结

1. **大对象 / 大数组 → 放到堆上**
2. **递归 → 改迭代 / 尾递归**
3. **必要时增加栈空间**
4. **智能指针递归析构注意循环引用**



## 详细解释栈帧

### 1. **栈帧是什么？**

- 栈帧（Stack Frame）也叫 **活动记录（Activation Record）**。
- 它是 **每次函数调用在栈上分配的一块内存区域**，用来保存：
  1. 函数的局部变量
  2. 函数参数
  3. 返回地址（函数执行完跳回哪里）
  4. 保存的寄存器（某些编译器会保存调用者寄存器）

每调用一次函数，就会在栈上压入一个新的栈帧，函数返回时弹出栈帧。

------

### 2. **栈帧的典型结构**

```
高地址
┌─────────────┐
│ 函数参数     │ <- main调用foo时传递的参数
├─────────────┤
│ 返回地址     │ <- 调用foo完成后要返回的位置
├─────────────┤
│ 保存的寄存器 │ <- 可能保存rbp, rbx等
├─────────────┤
│ 局部变量     │ <- int a, arr[], 对象等
└─────────────┘
低地址
```

- 栈通常 **向低地址增长**（不同平台可能不同）。
- 栈帧的大小在编译时或运行时确定（局部数组大小、局部对象）。

------

### 3. **函数调用与栈帧的流程**

1. 调用函数前，压入 **函数参数 + 返回地址**
2. 函数开始，**保存旧的栈基址寄存器 (EBP/RBP)**
3. 分配 **局部变量空间**
4. 执行函数
5. 返回前，释放局部变量空间，恢复寄存器
6. 弹出栈帧，跳回调用处

------

### 4. **示例：简单函数**

```
void foo(int x) {
    int a = 10;
    int b[5];
}

int main() {
    foo(42);
}
```

栈帧布局可能如下（假设栈向低地址增长）：

```
高地址
foo参数 x = 42
返回地址 (main的下一条指令)
保存的RBP
局部变量 a = 10
局部数组 b[5]
低地址
```

- 每次调用 `foo` 都会创建一个新的栈帧
- 递归时，每次调用都有独立栈帧

------

### 5. **栈帧与栈溢出**

- 栈溢出发生在 **栈空间用完**：
  - 递归太深 → 栈帧数量太多
  - 局部变量太大 → 单个栈帧占用过多

------

### 6. **栈帧与调试**

- 调试工具（gdb, lldb）可以通过栈帧查看：
  - 调用链（Call Stack）
  - 每层函数的局部变量值
  - 返回地址和寄存器状态

------

### ✅ 总结

- 栈帧 = **函数调用在栈上的内存块**
- 保存函数参数、返回地址、局部变量、寄存器
- 栈帧是 **函数调用和递归的基础**
- 栈溢出、本地变量访问越界、递归深度过大都和栈帧有关



## 移动构造如何实现的

移动构造的核心思想：**把资源的“所有权”从旧对象转移到新对象，而不是拷贝**。
 这样避免了深拷贝的开销。

### 移动构造函数做了什么？

1. **浅拷贝指针和元数据**（直接拿过来，不复制数据）。
2. **把源对象的指针置为 `nullptr`**（防止析构时释放同一块内存两次）。



# STL

## STL介绍

Standard Template Library，标准模板库，是C++的标准库之一，一套基于模板的容器类库，还包括许多常用的算法，提高了程序开发效率和复用性。

**STL包含6大部件：容器、迭代器、算法、仿函数、适配器和空间配置器。**

- 算法：包括查找算法、排序算法等等。

- 适配器：用来修饰容器等，比如queue和stack，底层借助了deque。
- 空间配置器：负责空间配置和管理，是一个实现了动态空间配置，空间管理，空间释放的类模板。

## vector

### vector描述

`std::vector` 是一个能够动态扩容的连续数组。

它有以下特点：

- 元素存储在一块连续内存中。
- 支持通过下标进行随机访问，时间复杂度为 `O(1)`。
- 尾部插入和删除效率较高。
- 中间插入、删除需要移动后续元素，时间复杂度通常为 `O(n)`。
- 当容量不足时，会重新申请更大的连续内存。

可以把 `vector` 理解为：

> 一个自动管理内存、能够动态扩容的数组。

### vector的底层原理

典型实现中，`vector` 内部通常维护三个指针：

```
T* start;
T* finish;
T* end_of_storage;
```

它们分别表示：

- `start`：第一个元素的位置。
- `finish`：最后一个有效元素之后的位置。
- `end_of_storage`：整块已分配内存之后的位置。

示意图：

```
start                finish              end_of_storage
  ↓                     ↓                       ↓
  | 已构造元素 | 已构造元素 | 未使用容量 | 未使用容量 |
  |<------- size ------->|
  |<--------------- capacity ---------------->|
```

因此：

```cpp
size() == finish - start;//表示当前已经存在的元素数量。
capacity() == end_of_storage - start;//表示当前已经申请的内存最多可以容纳多少个元素。
```

这里保存的是指针，不是“保存了三个迭代器”。

只是因为 `vector` 的元素连续存储，所以普通指针可以作为一种随机访问迭代器。

### vector内存增长机制

**当空间不够装下数据（vec.push_back(val)）时，会自动申请另一片更大的空间（1.5倍或者2倍），然后把原来的数据拷贝到新的内存空间，接着释放原来的那片空间**(gcc是2倍，vs下的mingw是1.5倍)

至于为什么是按照倍数扩容，也是为了效率考虑，元素越多的情况下，扩容后转移数据的代价越小。

至于为什么不是三倍四倍的扩大，是因为扩的太多会导致内存浪费，可能最后一次一下子扩大很多用不了。

### vector中的reserve和resize的区别

1. ### `reserve(n)`

   - 作用：预留 **容量**（capacity），让 `vector` 至少能装 `n` 个元素。
   - 不会改变当前元素个数（size），只是分配/扩充内存。
   - **元素数量不变**。
- `reserve()` 常用于提前知道大概元素数量的情况，可以减少扩容次数
  

  
   只申请空间，不创建元素
   
   因此，下面的代码错误：

   ```cpp
std::vector<int> v;
   v.reserve(5);

   v[0] = 10;  // 越界，size 仍然是 0
   ```
   
   正确写法：
   
   ```cpp
   v.push_back(10);
   ```
   
   
   
   ### `resize(n)`
   
   - 作用：改变 **元素个数**（size）。
   - 如果 `n` 比当前小，多余的元素会被销毁。
   - 如果 `n` 比当前大，会创建新元素（用默认值或给定值填充）。
   - **元素数量会改变**。
- 对于 `vector<int>`，新增元素会被值初始化为 `0`。
  
------

   ### 举个例子

   ```
   #include <iostream>
   #include <vector>
   using namespace std;
   
   int main() {
       vector<int> v;  // 空vector
   
       v.reserve(5);   // 容量 >= 5，但 size 还是 0
       cout << "reserve 后 size=" << v.size() << " capacity=" << v.capacity() << endl;
   
       v.resize(5);    // 真正增加了5个元素，每个默认值是0
       cout << "resize 后 size=" << v.size() << " capacity=" << v.capacity() << endl;
   
       return 0;
   }
   ```

   输出可能是：

   ```
   reserve 后 size=0 capacity=5
   resize 后 size=5 capacity5
   ```



### `clear()`、`erase()` 和容量

执行：

```
v.clear();
```

会销毁所有元素，并令：

```
v.size() == 0;
```

但一般不会释放已经申请的底层存储空间：

```
v.capacity()
```

通常保持不变。

类似地：

```
v.erase(v.begin(), v.end());
```

也只是删除元素，通常不会缩小容量。

这样设计是为了后续再次插入元素时，可以复用原来的内存。



### vector中size()和capacity()的区别

- **`size()`**
  - 表示当前 **实际存放的元素个数**。
  - 就是现在里面“有多少东西”。
- **`capacity()`**
  - 表示当前 **底层内存最多能容纳多少元素**（不用重新分配的情况下）。
  - 就是“书包能装多少”。



### vector的元素类型可以是引用吗？

- C++ 标准规定：`vector` 的元素类型必须是 **可复制（CopyAssignable/CopyConstructible）** 的完整类型。
- **引用（reference）不是对象**，只是某个对象的别名，不能被重新赋值成别的对象，也不能单独存放在容器里。
- 所以 `vector<int&>`、`vector<const int&>` 这种写法会编译报错。



### vector迭代器失效的情况

#### 1. 容量变化导致失效

当 `vector` 的 **容量（capacity）不够用**，需要重新分配内存时：

- 所有迭代器（iterator）、指针、引用都会 **全部失效**。
- 典型操作：
  - `push_back()`（可能触发扩容）
  - `insert()`（在容量不够时扩容）
  - `resize()`（如果导致扩容）
  - `reserve()`（如果分配了更大的空间）

------

#### 2. 元素移动/删除导致部分失效

- **erase(pos)**：
  - 指向被删除元素的迭代器失效。
  - 该位置之后的所有迭代器也失效（因为元素前移了）。
- **insert(pos, x)**（在容量足够的情况下）：
  - 指向插入位置及其之后的迭代器失效。
  - 之前的迭代器保持有效。







### vector在栈还是堆，能开10万个元素的vector吗，怎么扩容的，怎么开辟内存

#### 1. `vector` 自己在 **栈** 还是 **堆**？

- **对象本身**（比如 `size`、`capacity`、指向数据的指针等元信息）在你定义它的地方。
  - 如果你在函数里写 `vector<int> v;`，那这个对象本身在 **栈上**。
- **元素存储区**（真正存放数据的数组）一定在 **堆上**，由 `new`/`operator new` 分配。
  - 所以 `vector<int>` 本质上就是在栈里放一个“小控制器”，控制着一块堆内存。

------

#### 2. 能不能开 10 万个元素？

可以。

- 假设 `vector<int> v(100000);`
- 每个 `int` 占 4 字节，总共大概 400 KB 内存。
- 这点空间对现代电脑来说很小（一般堆能用几百 MB 甚至 GB）。

------

#### 3. `vector` 扩容机制

- 当你 `push_back()` 时，如果 `size < capacity`，直接放进去。
- 如果 `size == capacity`，会触发扩容：
  1. **分配一块更大的新内存**（通常是原来的 2 倍左右，标准没强制，编译器自己决定）。
  2. **把原来数据复制/移动到新内存里**。
  3. **释放旧内存**。
  4. 更新 `capacity`。

因此扩容是 **指数增长**，这样保证了整体 `push_back` 平摊下来是 O(1)。

------

#### 4. 内存开辟原理

- `vector` 内部用 `allocator`（默认就是 `std::allocator`），底层其实就是调用 `operator new` 在堆上分配一大块连续内存。

- 比如：

  ```
  vector<int> v;
  v.reserve(100000); // 底层差不多相当于 new int[100000]
  ```

- 析构时 `~vector()` 会自动调用 `delete[]` 释放。



### vector作为函数返回值用法

1. 可以直接按值返回 `vector`：

   ```
   std::vector<int> createVector() {
       std::vector<int> result;
   
       result.push_back(1);
       result.push_back(2);
       result.push_back(3);
   
       return result;
   }
   ```

   调用：

   ```
   std::vector<int> v = createVector();
   ```

   现代 C++ 中通常不会发生昂贵的完整拷贝。

   原因包括：

   - RVO；
   - NRVO；
   - 移动语义。

   ### RVO

   直接返回临时对象：

   ```
   std::vector<int> createVector() {
       return std::vector<int>{1, 2, 3};
   }
   ```

   编译器可以直接在调用方的返回值位置构造对象。

   ### NRVO

   返回具名局部变量：

   ```
   std::vector<int> createVector() {
       std::vector<int> result{1, 2, 3};
       return result;
   }
   ```

   编译器通常也会直接在调用方空间中构造 `result`。

   即使没有执行 NRVO，`vector` 也通常可以通过移动构造，将内部指针转移给返回值，而不需要逐个复制元素。

   因此，现代 C++ 推荐直接按值返回：

   ```
   std::vector<int> createVector();
   ```

   通常没有必要为了避免复制而改成：

   ```
   void createVector(std::vector<int>& output);
   ```

   后者只有在需要复用已有容器、表达输出参数或具有特殊接口要求时才考虑。



### emplace_back和push_back

**相同**

emplace_back和push_back都支持左值和右值的传入。

我们这里就说类元素，不说内置和基本类型了。

传入左值的时候，会调用拷贝构造函数构造出一个匿名对象，然后将该对象存储到vector中

传入右值的时候，调用的是两个函数的移动构造函数构。

**不同**

```
people.push_back(Person("Alice", 25));
```

先形成一个 `Person` 对象，再将它放入 `vector`。具体是否发生额外移动，可能受复制消除影响。

```
people.emplace_back("Alice", 25);
```

直接传递构造参数，在目标位置构造。

不过不要认为 `emplace_back()` 永远比 `push_back()` 更快。

当已经有一个对象时：

```
Person p("Alice", 25);

people.push_back(p);
people.emplace_back(p);
```

两者通常都需要拷贝构造。

而且 `emplace_back()` 可能调用一些原本不希望调用的显式构造函数，因此应根据语义选择：

- 已经有对象：优先考虑 `push_back`。
- 手里只有构造参数：可以使用 `emplace_back`。



### 一个vetor内存很大但实际我只用了很小一部分怎么解决

#### 1. **释放多余容量**

```
vector<int> v;
// ... 做一些操作，容量可能很大
v.shrink_to_fit(); // 请求收缩到刚好够 size 的容量
```

- 注意：`shrink_to_fit()` 只是一个 **请求**，编译器可以选择不执行（但大部分实现都会收缩）。

------

#### 2. **交换技巧（保证收缩）**

```
vector<int>(v).swap(v);
```

- 解释：
  - `vector<int>(v)` 会创建一个 **只拷贝有效元素的新 vector**，它的 `capacity == size`。
  - `swap` 后，原来的大容量内存会被释放。

------

#### 3. **换容器（如果频繁删元素）**

- 如果经常出现“容量远大于实际使用”的情况，`vector` 可能不是最合适的容器。
- 例如：
  - 需要频繁增删 → 用 `deque`、`list`。
  - 需要节省内存但偶尔扩容 → 手动控制 `reserve` 和 `shrink_to_fit`。



### vector元素是指针类型

清空 vector 数据时，如果保存的数据项是指针类型，需要逐项 delete，否则会造成内存泄漏。

或者指定delete方法，再或者vector里直接保存智能指针



### 元素移动还是复制

扩容时，`vector` 会尽量把旧元素移动到新内存。

但是否一定移动，要看元素类型。

如果类型的移动构造函数可能抛出异常，而拷贝构造函数可用，标准库为了维持异常安全，可能选择拷贝。

例如：

```
class A {
public:
    A(const A&);       // 可拷贝
    A(A&&);            // 移动可能抛异常
};
```

某些情况下，扩容时可能调用拷贝构造。

通常建议把不会抛异常的移动构造标记为：

```
noexcept
```

例如：

```
A(A&& other) noexcept;
```

这有助于 `vector` 在扩容时使用移动操作。



### Vector如何释放空间?

vector的内存占用空间只增不减，比如你首先分配了10,000个字节，然后erase掉后面9,999个，留下一个有效元素，但是内存占用仍为10,000个。

**所有的内存空间是在vector析构时候才能被系统回收。**

empty()用来检测容器是否为空的，clear()可以清空所有元素。但是即使clear()，vector所占用的内存空间依然如故，无法保证内存的回收。

如果需要空间动态缩小，可以考虑使用deque。如果vector，可以用swap()来帮助你释放内存。

```c++
vector(Vec).swap(Vec); //将Vec的内存清除； 
vector().swap(Vec); //清空Vec的内存；
```

## deque

### deque是什么

`deque` 全称是 **double-ended queue（双端队列）**。

它支持在容器的头部和尾部高效地插入、删除元素：

```
deque.push_front(x);
deque.push_back(x);

deque.pop_front();
deque.pop_back();
```

`deque` 和 `vector` 都支持随机访问：

```
deque[i];
deque.at(i);
```

访问单个元素的时间复杂度都是 `O(1)`。

但两者的底层存储结构不同：

- `vector`：使用一整块连续内存
- `deque`：使用多块小型连续内存组合存储

因此，不能把 `deque` 描述成“连续线性空间”。更准确的说法是：

> `deque` 在逻辑上表现为连续序列，但物理内存通常是分段连续的。

### deque容器的底层存储机制

#### 1. 基本结构

- `deque` 通常采用：

  > **分段数组 + map 控制表**

  大致结构如下：

  ```
                       map
                ┌──────┬──────┬──────┐
                │  *   │  *   │  *   │
                └──┬───┴──┬───┴──┬───┘
                   │      │      │
                   ▼      ▼      ▼
                block0  block1  block2
                [....]  [....]  [....]
  ```

- **block（缓冲区）**：

  - 每个 `block` 是一块连续内存，用来存放若干个元素。

    ```
    block0: [元素][元素][元素][元素]
    block1: [元素][元素][元素][元素]
    block2: [元素][元素][元素][元素]
    ```

    一个 block 能存放多少个元素由具体实现决定，通常会结合：

    - 元素类型的大小
    - 标准库实现策略
    - 目标平台

    因此，不能认为 block 一定存放固定的 64、128 或 512 个元素。

- **map（控制表）**：

  - 这里的 `map` 不是 `std::map` 容器。
  
    它本质上通常是一个指针数组，其中每个指针指向一个 block：
  
    ```
    block_pointer map[];
    ```
  
    例如：
  
    ```
    map[0] -> block0
    map[1] -> block1
    map[2] -> block2
    ```
  
    通过 map，`deque` 可以管理多块互不连续的内存。

------

#### 2. 元素访问

- `deque[i]`：
  1. 用 i 算出落在哪个 block：`block_index = i / block_size`
  2. 再算出 block 内偏移：`offset = i % block_size`
  3. 直接访问 `map[block_index][offset]`
- 所以访问仍然是 O(1)，但不一定是连续内存

------

#### 3. 两端操作效率

- **push_front / push_back**：
  - 如果当前首尾 block 满了，就分配一个新的 block
  - 仅需要更新 map（添加 block 指针），不会移动整个数据
- **中间插入/删除**：
  - 就像 vector，需要搬动元素 → O(n)

#### 

**问：如果 map 数组满了怎么办？**

答：再申请一块更大的连续空间供 map 数组使用，将原有数据（很多指针）拷贝到新的 map 数组中，然后释放旧的空间。

```
map 扩容时复制的是 block 指针，不是 block 中存放的所有元素。
```



### deque的iterator

#### deque 迭代器内部四个关键指针

1. **`cur`**
   - 指向 **当前缓冲区（block）中的当前元素**
   - ++ 或 -- 操作主要就是在 `cur` 内移动，超出 block 范围时跳到下一个 block
2. **`first`**
   - 指向 **当前 block 的起始位置**
   - 用于判断当前迭代器在 block 内的位置
3. **`last`**
   - 指向 **当前 block 的结束位置**（通常是 block 可用空间尾部）
   - 判断是否越界，需要切换到下一个 block
4. **`node`**
   - 指向 **map 中当前 block 的指针**（map 是管理所有 block 的数组）
   - 用来快速找到下一个或上一个 block

------

#### 补充说明

- `deque` 的 **map**：
  - 存放每个 block 的指针（不是元素本身）
  - 当 block 不够用时，可以扩展 map，分配更多 block 指针
- 迭代器移动时：
  - 如果在 block 内：只修改 `cur`
  - 如果跨 block：更新 `node`，然后 `cur = first`

### deque和vector的区别

- ## 1. **底层存储结构**

  | 容器     | 内存连续性   | 底层结构                                          |
  | -------- | ------------ | ------------------------------------------------- |
  | `vector` | 是连续内存   | 单块连续数组，元素紧密排列                        |
  | `deque`  | 不是完全连续 | 分段数组 + map，每个 block 连续，block 之间不连续 |

  ------

  ## 2. **插入/删除效率**

  | 操作                   | `vector`               | `deque`                   |
  | ---------------------- | ---------------------- | ------------------------- |
  | push_back / pop_back   | O(1) 平摊              | O(1) 平摊                 |
  | push_front / pop_front | O(n)（要搬移所有元素） | O(1) 平摊（分配新 block） |
  | 中间插入/删除          | O(n)                   | O(n)                      |

  > 所以 `deque` 支持两端高效操作，而 `vector` 只能尾部高效。

  ------

  ## 3. **迭代器**

  | 特性     | `vector`                 | `deque`                                       |
  | -------- | ------------------------ | --------------------------------------------- |
  | 类型     | 随机访问迭代器           | 随机访问迭代器                                |
  | 内存连续 | 是                       | 否（跨 block 时迭代器内部需要 node/pointers） |
  | 失效规则 | 扩容/中间插入/删除会失效 | 两端插入一般不失效，中间插入/删除会失效       |

  ------

  ## 4. **内存占用和空间增长**

  - `vector`：连续内存，扩容通常 2 倍，尾部操作快，但前端操作慢
  - `deque`：分段数组，尾/头操作都快，内存稍有浪费（每个 block 独立）

  ------

  ## 5. **访问效率**

  - `vector[i]`：连续内存，CPU 缓存友好 → 最快
  - `deque[i]`：需要先找 block 再找 block 内索引 → 略慢

  ------

  ## 6. **总结适用场景**

  - **vector**
    - 元素尾部频繁添加/删除
    - 需要快速随机访问
    - 内存连续很重要（比如与 C 接口、音视频缓冲）
  - **deque**
    - 两端频繁插入/删除（紧急任务和普通任务）
    - 随机访问也要求 O(1)
    - 不在乎内存不连续

## stack

stack是一个容器适配器，也就是表示某种操作，底层的数据结构可以多种多样

不过一般默认底层容器是：

```cpp
std::deque<T>
```

常见选择：

```
std::stack<int, std::deque<int>> st1;
std::stack<int, std::vector<int>> st2;
std::stack<int, std::list<int>> st3;
```

是⼀种先进后出的数据结构，只有⼀个出口，stack 允许从最顶端新增元素，移除最顶端元素，取得最顶端元素。 deque 是双向开口的数据结构，所以使⽤ deque 作为底部结构并封闭其头端开口，就形成了⼀个 stack。

###  `stack` 常用接口

```
std::stack<int> st;

st.push(10);       // 栈顶插入元素
st.emplace(20);    // 在栈顶直接构造元素
st.pop();          // 删除栈顶元素，不返回元素
st.top();          // 获取栈顶元素
st.empty();        // 判断栈是否为空
st.size();         // 返回元素数量
st.swap(other);    // 交换两个栈
```



### `top()` 返回的是值还是引用？

返回引用。

因此可以修改栈顶元素：

```
std::stack<int> st;
st.push(10);

st.top() = 20;

std::cout << st.top();  // 20
```

## vector, list, map等容器使用场合是什么？

顺序容器首选 vector，关联容器首选 unordered_map。

| 容器                    | 特点                                                         | 适用场合                                                     |
| ----------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **vector**              | - 连续内存 - 随机访问快 O(1) - 尾部插入/删除快 O(1) 平摊 - 中间插入/删除慢 O(n) | - 尾部频繁添加元素 - 需要快速索引访问 - 内存连续很重要（音视频缓存、数组接口） |
| **list**                | - 双向链表 - 插入/删除任意位置 O(1)（已知迭代器） - 随机访问慢 O(n) - 内存开销大 | - 中间插入/删除频繁 - 不需要随机访问 - 元素大或移动成本高    |
| **deque**               | - 分段数组 + map - 两端插入/删除 O(1) 平摊 - 随机访问 O(1) - 内存不连续 | - 两端都需要高效插入/删除 - 随机访问也需要 O(1) - 内存稍微浪费可以接受 |
| **map**                 | - 平衡树（红黑树） - 有序 key - 插入/删除/查找 O(log n) - 自动排序 | - 需要按 key 排序或快速查找 - 元素需要唯一 key - 频繁插入/删除 |
| **unordered_map**       | - 哈希表 - 插入/查找平均 O(1) - 无序                         | - 只关心 key 查找快，不关心顺序 - 频繁插入/查找              |
| **set / unordered_set** | - 类似 map，但只存 key - 自动排序 / 哈希表                   | - 去重 - 查找是否存在元素 - 按顺序或快速查找                 |



## 关联式容器（map,multimap,set,multiset）

### 为何关联容器的插入删除效率一般比用其他序列容器高？

答：关联容器一般指map,multimap,set,multiset这四种底层实现都是红黑树。**对于关联容器来说，存储的只是节点。插入删除只是节点指针的换来换去，不需要做内存拷贝和内存移动。**



### 为何每次insert之后，以前保存的iterator不会失效？

因为每次只是节点指针的改变，每个节点的内存没有改变。iterator就是指向每个节点内存的指针，所以插入之后，该指针是不会变的。



### 为何map和set不能像vector一样有个reserve函数来预分配数据？

`vector` 的元素放在一整块连续内存中，而 `map`、`set` 的元素通常是一个节点一块内存，没什么“容量”可以提前预留。



### 当数据元素增多时（10000和20000个比较），map和set的插入和搜索速度变化如何？

`map` 和 `set` 通常基于红黑树实现，插入和查找复杂度都是 O(log n)。元素数量从 10000 增加到 20000 时，树的高度大约只增加一层，所以单次插入和搜索只会略微变慢，而不会慢一倍。但如果比较的是插入全部数据的总时间，因为元素数量也翻倍了，总耗时大约会增加到两倍多。



### map用[]越界会发生什么？

- 在 C++ 的 `map` 中，使用 `operator[]` 访问一个不存在的 key，会 **自动创建一个新元素**，并用 **value_type 的默认构造函数** 初始化其值。

  ------

  ## 1. 举例说明

  ```
  #include <map>
  #include <iostream>
  using namespace std;
  
  int main() {
      map<int, string> m;
  
      cout << m[10] << endl;  // key=10 不存在 → 自动插入 → value=""（string 默认构造为空）
      
      m[20] = "hello";        // key=20 不存在 → 插入新元素，赋值 "hello"
      
      cout << m.size() << endl; // 输出 2
  }
  ```

  - key = 10 不存在 → 插入新节点 → value 是默认值 `""`
  - key = 20 → 新节点，赋值为 `"hello"`
  - map 大小增加了

### map和set为什么用红黑树

高度越小越好，BST这种有特殊情况，普通 BST（Binary Search Tree）在插入顺序不均衡时会退化成链表

AVL树（自平衡二叉搜索树）要求严格平衡，导致每次自适应的时候效率低一点。所以综合来说红黑树是最优秀的

### map中[]与find的区别？

1. map的下标运算符[]的作用是：将key作为下标去执行查找，并返回对应的值；如果不存在这个key，就将一个具有该关键码和值类型的默认值的项插入这个map。
2. map的find函数：用key执行查找，找到了返回该位置的迭代器；如果不存在这个关键码，就返回尾迭代器。



## 容器内部删除一个元素

```
it = container.erase(it);
```

意思是：

1. 删除 `it` 当前指向的元素；
2. `erase` 返回下一个还有效的迭代器；
3. 再把这个新迭代器交给 `it`。

#### 为什么不能这样写

```
v.erase(it);
++it;
```

因为删除后，原来的 `it` 已经失效了。

你可以把失效理解成：

> 这个迭代器已经不能用了，再对它 `++` 是错误的。



## allocator的使用

`allocator` 是 C++ 标准库提供的 **内存分配器**，可以手动控制内存的分配和对象构造，底层容器（如 `vector`、`map`）默认就用它。

------

### 1. allocator 的核心接口

假设类型为 `T`：

| 方法                    | 作用                                           |
| ----------------------- | ---------------------------------------------- |
| `allocate(n)`           | 分配 n 个 `T` 的原始未初始化内存（不调用构造） |
| `deallocate(p, n)`      | 释放之前分配的 n 个对象的内存                  |
| `construct(p, args...)` | 在指针 p 所指向内存上构造对象（调用构造函数）  |
| `destroy(p)`            | 调用指针 p 指向对象的析构函数                  |

------

### 2. 示例代码

```
#include <memory>
#include <iostream>
using namespace std;

int main() {
    allocator<int> alloc;          // 创建一个 int 类型的 allocator
    int* p = alloc.allocate(3);    // 分配 3 个 int 的原始内存

    // 构造对象
    alloc.construct(p, 10);        // p[0] = 10
    alloc.construct(p+1, 20);      // p[1] = 20
    alloc.construct(p+2, 30);      // p[2] = 30

    for(int i = 0; i < 3; i++)
        cout << p[i] << " ";
    cout << endl;

    // 销毁对象
    for(int i = 0; i < 3; i++)
        alloc.destroy(p+i);

    // 释放内存
    alloc.deallocate(p, 3);

    return 0;
}
```

### 输出：

```
10 20 30
```

------

### 3. 使用场景

1. **自定义容器**
   - 手动管理对象的分配/构造/析构
2. **性能优化**
   - 避免重复分配/拷贝，提高效率
3. **理解 STL 容器底层**
   - `vector`、`list`、`map` 默认都用 allocator 分配内存



## 迭代器的底层机制和失效的问题

**迭代器失效的定义：对容器的操作影响了元素的存放位置，称为迭代器失效。**

失效情况分为三种：

1. 当容器调用`erase()`方法后，当前位置到容器末尾元素的所有迭代器全部失效。
2. 当容器调用`insert()`方法后，当前位置到容器末尾元素的所有迭代器全部失效。
3. 如果容器扩容，在其他地方重新又开辟了一块内存。原来容器底层的内存上所保存的迭代器全都失效了。

通过迭代器可以在不了解容器内部原理的情况下遍历容器



**序列式容器失效**

**失效原因：**因为 vetor、deque 使用了连续分配的内存，`erase`操作删除一个元素导致后面所有的元素都会向前移动一个位置，这些元素的地址发生了变化，所以当前位置到容器末尾元素的所有迭代器全部失效。

**解决办法：**由于`erase`可以返回下一个有效的iterator，因此`q.earse(it)`不行，但是`it=q.erase(it)`可以

```c++
int main() {
	vector<int> q{ 1,2,3,4,5,6 };
	// 在这里想把大于2的元素都删除
	for (auto it = q.begin(); it != q.end(); it++) {
		if (*it > 2)
			q.erase(it); // 这里就会发生迭代器失效
	}
	// 打印结果
	for (auto it = q.begin(); it != q.end(); it++) {
		cout << *it << " ";
	}
	cout << endl;
	return 0;
}

//解决办法
for(auto it=q.begin();it!=q.end();)
{
    if(*it>2)
    {
    	it=q.erase(it); // 这里会返回指向下一个元素的迭代器，因此不需要再自加了
    }
    else
    {
    	it++;
    }
}
```

**链表式容器失效**和**关联式容器失效**

**失效原因：**链表的插入和删除节点不会对其他节点造成影响，因此只会使得当前的iterator失效

**解决办法：**利用`erase`可以返回下一个有效的iteratord的特性，或者直接iterator++

```c++
//方法1
for (iter = cont.begin(); it != cont.end();)
{
   (*iter)->doSomething();
   if (shouldDelete(*iter))
      cont.erase(iter++);
   else
      iter++;
}
//方法2
for (iter = cont.begin(); iter != cont.end();)
{
   (*it)->doSomething();
   if (shouldDelete(*iter))
      iter = cont.erase(iter);  //erase删除元素，返回下一个迭代器
   else
      ++iter;
}
```



## 迭代器和指针的区别

迭代器实际上是对“遍历容器”这一操作进行了封装。迭代器不是指针，是类模板。重载了指针的一些操作符如：，->, * , ++, --等。

看实际用法，注意用到了iterator，而不是直接一个指针

```
vector<int> nums = {10, 20, 30};

vector<int>::iterator it = nums.begin();

cout << *it;  // 10
++it;
cout << *it;  // 20
```



## 迭代器的种类

- 迭代器（iterator）是 STL 的核心概念，不同类型迭代器支持的操作不同，按能力可以分为 **五大类**：

  ------

  ## 1. 输入迭代器（Input Iterator）

  - **用途**：只读访问序列一次
  - **操作**：
    - `*it` → 读取元素
    - `++it` → 前进
  - **特点**：只能单向遍历，不能回退
  - **常见容器**：istream_iterator

  ------

  ## 2. 输出迭代器（Output Iterator）

  - **用途**：只写，不读
  - **操作**：
    - `*it = value` → 写入元素
    - `++it` → 前进
  - **特点**：只能单向写入
  - **常见容器**：ostream_iterator

  ------

  ## 3. 前向迭代器（Forward Iterator）

  - **用途**：既能读又能写，单向遍历
  - **操作**：
    - `*it` → 读/写
    - `++it` → 前进
  - **特点**：可以多次遍历序列
  - **常见容器**：`forward_list`、`unordered_set`、`unordered_map`

  ------

  ## 4. 双向迭代器（Bidirectional Iterator）

  - **用途**：前向+后向遍历
  - **操作**：
    - `*it` → 读/写
    - `++it` / `--it` → 前进/后退
  - **特点**：适合链表等双向结构
  - **常见容器**：`list`、`set`、`map`、`multiset`、`multimap`

  ------

  ## 5. 随机访问迭代器（Random Access Iterator）

  - **用途**：可以像指针一样随机访问
  - **操作**：
    - `*it` → 读/写
    - `++it` / `--it` → 前后移动
    - `it + n` / `it - n` → 跳到任意位置
    - `it1 - it2` → 距离
    - `it[n]` → 访问下标元素
  - **特点**：功能最强，支持所有 STL 算法
  - **常见容器**：`vector`、`deque`、`array`





## 仿函数

### 1. 基本定义

```
#include <iostream>
using namespace std;

// 定义仿函数
struct Add {
    int operator()(int a, int b) const {
        return a + b;
    }
};

int main() {
    Add add;
    cout << add(2, 3) << endl;  // 调用 operator() → 输出 5
}
```

- `Add` 就是一个仿函数
- `add(2,3)` 实际是调用了 `Add::operator()(2,3)`

------

### 2. 仿函数的特点

1. **像函数一样调用**
   - `f(args...)` 与普通函数调用一样
2. **可以有状态**
   - 可以存储成员变量，记住一些信息
3. **可作为模板参数**
   - STL 算法中常用仿函数，如 `sort(v.begin(), v.end(), Compare)`
4. **可以内联**
   - 编译器可优化成内联调用，比函数指针更快

## c++STl中vector、list和map插入1000万个元素，消耗对比

假设插入 **1000 万个 `int`**：

| 容器     | 插入速度 | 内存消耗                            | 原因                                                   |
| -------- | -------- | ----------------------------------- | ------------------------------------------------------ |
| `vector` | **最快** | **最少**，约 40MB，另有预留容量     | 连续内存，尾插开销小；提前 `reserve()` 更快            |
| `list`   | 较慢     | **很大**，常见约 200～300MB         | 每个元素都要单独分配节点，还保存前后两个指针           |
| `map`    | **最慢** | **最大或接近最大**，可能 400MB 以上 | 每次插入要分配红黑树节点，并进行 `O(log n)` 查找和调整 |

## vector中push_back一个string会有什么问题

### vector push_back 可能的问题

1. **扩容慢**
   - vector 内存是连续的，如果容量不够，要重新分配更大的内存，并搬运原来的元素 → 时间开销大。
2. **copy 构造开销大**
   - 对于像 `std::string` 这种可能包含大量字符的对象，拷贝构造会复制内部数据 → 性能消耗大。

------

### 对策

1. **预分配容量**：

```
vec.reserve(1000); // 预先分配足够空间，减少扩容
```

1. **使用移动语义**：

```
vec.push_back(std::move(s)); // 不拷贝字符串内容，只搬指针
```

- **效果**：
  - 避免频繁扩容 → 提高效率
  - 避免拷贝构造开销 → 提升性能

## unordered_map和unordered_set的区别与共同点，底层原理

### 共同点

1. **底层原理**
   - 都基于 **哈希表（hash table）** 实现。
   - 元素的位置由哈希函数 `hash(key)` 决定。
   - 发生冲突时（两个元素算出的哈希值相同），通常用 **链表 / 拉链法（C++11）** 或 **桶+链式结构** 来解决。
   - 插入、查找、删除的平均时间复杂度都是 **O(1)**。
2. **特点**
   - 元素是**无序**存储的，遍历时顺序不可预测。
   - 都需要定义**哈希函数**和**相等判断函数**。
   - 当元素数量变多时，哈希表会 **rehash（扩容，增加桶数）**。

------

### 区别

| 特性           | `unordered_map`                     | `unordered_set`                                 |
| -------------- | ----------------------------------- | ----------------------------------------------- |
| 存储内容       | **键值对 (key, value)**             | **单个键 (key)**                                |
| 访问方式       | 用 `map[key]` 或 `find(key)` 获取值 | 只能用 `find(key)` 判断是否存在                 |
| 是否允许重复键 | 不允许                              | 不允许（如果想允许，要用 `unordered_multiset`） |
| 使用场景       | 需要通过 key 找到对应 value         | 只需要判断 key 是否存在、存储集合元素           |

------

### 底层原理（简化版）

1. **哈希函数**：把 `key` 映射到一个整数。
2. **取模运算**：`index = hash(key) % bucket_count` → 确定落在哪个桶里。
3. **桶（bucket）**：每个桶存一个链表或结构，解决冲突。
4. **负载因子 (load factor)**：`元素个数 / 桶数`，过大时会触发 rehash（扩容）。

## Double Buffer：用双缓冲减少读写锁竞争

### 1. 适用场景

双缓冲适合以下场景：

- 一个写线程负责更新数据
- 一个或多个读线程频繁读取数据
- 读操作远多于写操作
- 读线程可以接受读取某个完整版本的数据

例如：

- 配置信息更新
- 游戏画面渲染
- 音频、视频帧处理
- 统计数据快照



### 1. 核心思想

- 准备两份数据：

  ```
  bufferA
  bufferB
  ```

  其中：

  - 一份提供给读线程读取
  - 另一份由写线程修改
  - 写线程完成修改后，再把“当前可读缓冲区”切换到新数据

  例如：

  ```
  初始状态：
  
  读线程读取 bufferA
  写线程更新 bufferB
  ```

  当 `bufferB` 更新完成后：

  ```
  读缓冲区切换为 bufferB
  ```

  之后，新进入的读线程开始读取 `bufferB`。

  这样，写线程不会直接修改读线程当前正在使用的数据。



------

### 2. 工作流程

```
         生产者线程                 消费者线程
         ---------                 ---------
写入 bufferA/B                 读取 bufferB/A
    │                             │
    └── 当写完 → 切换指针 ──────> 读取线程开始读新缓冲
```

- 写线程完成一次写入后，将缓冲指针切换
- 读线程读取旧缓冲，不会被写线程覆盖
- 下次再切换时，两线程仍然互不干扰

这里最重要的一点是：

> 切换之后，只能保证新读线程会读取新缓冲区，不能保证旧读线程已经停止读取旧缓冲区。

因此，写线程不能在切换后立即修改 `bufferA`。

必须确认没有读线程继续使用 `bufferA`，才能安全地复用它。



为了保证旧缓冲区已经没有读线程使用，通常还需要以下机制之一：(看一眼就行，不好记)

- 读者引用计数
- 读写完成标志
- 等待读线程退出旧缓冲区
- `shared_ptr` 管理对象生命周期
- RCU、Epoch 等内存回收机制
- 明确的一生产者、一消费者同步协议

如果只有一个生产者和一个消费者，并且双方严格按照固定节奏交换缓冲区，实现会比较简单。

如果存在多个读线程，生命周期管理会明显复杂。

------

### 4. 优势

1. **无锁** → 避免锁开销和线程阻塞
2. **高性能** → 适合实时场景（音频、视频帧处理）
3. **简单易懂** → 只需两块缓冲区 + 原子指针/标志位



## 内存池

#### 内存池概述

内存池（Memory Pool）是一种 **预先分配内存块、重复利用的内存管理技术**，主要目的是 **提高频繁分配/释放小对象的效率**，避免系统频繁向操作系统申请内存导致的开销和碎片。其实就是为了避免来回开辟和释放空间，给你一块儿内存你去用吧，不够再来，反正就是根据一些规则，判断哪块儿安全的，就随便用。手动管理内存了属于是。

------

#### 1. 核心思想

- **提前申请一大块连续内存**
- **划分固定大小的小块**（或按需求大小分块）
- **分配小对象时直接拿池里的内存，不再调用 `new`/`malloc`**
- **释放对象时不回收给系统，只放回池中重复使用**

------

#### 2. 优势

内存池避免频繁调用系统或通用内存分配器，适合频繁创建和销毁的小对象。

例如：

- 网络连接对象
- 定时器节点
- 消息节点
- 游戏中的子弹、粒子
- 链表节点
- 协程对象

#### 减少内存碎片

如果程序频繁申请不同大小的内存，堆中可能出现很多分散的小空闲区域。

内存池统一管理固定大小或分类大小的内存块，可以在一定程度上减少碎片。

#### 提高缓存局部性

内存池中的对象通常存放得比较集中，CPU 访问相邻对象时，更容易命中缓存。

#### 内存使用更可控

内存池可以限制最大容量，适用于实时系统、游戏服务器或嵌入式系统。





## c语言连接数据库的步骤

## 完整流程

```
初始化连接对象
      ↓
连接 MySQL 服务器
      ↓
设置字符集
      ↓
执行 SQL
      ↓
判断 SQL 类型
 ┌──────────────┴──────────────┐
增、删、改                    查询
判断执行结果                  获取结果集
处理事务                      遍历结果集
                             释放结果集
 └──────────────┬──────────────┘
             关闭连接
```



## 简单代码示例

```cpp
#include <mysql/mysql.h>
#include <iostream>

int main() {
    // 1. 初始化连接对象
    MYSQL* mysql = mysql_init(nullptr);

    if (mysql == nullptr) {
        std::cerr << "MySQL 初始化失败" << std::endl;
        return 1;
    }

    // 2. 连接服务器
    if (mysql_real_connect(
            mysql,
            "127.0.0.1",
            "root",
            "password",
            "test_db",
            3306,
            nullptr,
            0) == nullptr) {
        std::cerr << "连接失败：" << mysql_error(mysql) << std::endl;
        mysql_close(mysql);
        return 1;
    }

    // 3. 设置字符集
    mysql_set_character_set(mysql, "utf8mb4");

    // 4. 执行查询
    const char* sql = "SELECT id, name FROM users";

    if (mysql_query(mysql, sql) != 0) {
        std::cerr << "查询失败：" << mysql_error(mysql) << std::endl;
        mysql_close(mysql);
        return 1;
    }

    // 5. 获取结果集
    MYSQL_RES* result = mysql_store_result(mysql);

    if (result == nullptr) {
        std::cerr << "获取结果集失败：" << mysql_error(mysql) << std::endl;
        mysql_close(mysql);
        return 1;
    }

    // 6. 遍历结果集
    unsigned int columnCount = mysql_num_fields(result);
    MYSQL_ROW row;

    while ((row = mysql_fetch_row(result)) != nullptr) {
        for (unsigned int i = 0; i < columnCount; ++i) {
            std::cout << (row[i] ? row[i] : "NULL") << " ";
        }

        std::cout << std::endl;
    }

    // 7. 释放结果集
    mysql_free_result(result);

    // 8. 关闭连接
    mysql_close(mysql);

    return 0;
}
```
